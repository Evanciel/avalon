> 설계: `graph-architect` / v1 → v2 → v3 → **v4 2026-08-12 (딥리서치 12에이전트 + 적대적 반증 3건 + 완결성 비평 반영)**

### 1차 조사의 사실 오류 — 3건

- **`Compiled AI`는 실물 제품이 아니다.** arXiv 2604.05150 프리프린트이며 공개된 것은 평가 프레임워크(스타 4)뿐. 논문 스스로 *"Code Factory invocations rely on runtime LLM calls"* 를 한계로 인정 — H=0 결정론은 control plane 한정
- **"eBay 워크플로 DSL(2025-12)"은 오귀속.** 해당 논문(2512.19769)은 PayPal
- **"④는 실행된 적 없다"는 계수 오류.** `evolve_learning` 9건이 실존하나, 이는 `/evolve` 슬래시 명령의 자유형식 산출물이지 그래프 IR과 조인되는 아카이브가 아니다 → **G8 기준 보유 자산은 0건**

### 완결성 비평이 잡아낸 것 — 종합 자체의 오류

**계측 부채는 존재하지 않는다.** 종합은 "Workflow journal에 timestamp가 없어 지연·비용을 못 잰다"며 G9를 신설했으나, 직접 실측한 결과 `wf_*.json` **316개 전부** `timestamp`·`durationMs`·`totalTokens` **100% 기록 중**(합계 4.18억 토큰, 중앙값 24분).

> 부채는 **"계측 부재"가 아니라 "계측 소비 부재"** 다. 4개월간 아무도 이 데이터를 열지 않았다. 처방이 정반대다.

## 정의 — 4단 (변경 없음)

> **어떤 에이전트든 스킬로 부르면, 그 프로젝트에 맞는 실행 그래프를 스스로 구성하고 완료까지 돌리는 툴체인.**

비유는 `gcc` — 컴파일러가 아니라 **드라이버 + 컴파일러 툴체인**.

| 단 | 하는 일 | 판정 | 자산 |
|---|---|---|---|
| **① FRONTEND** | 프로젝트 분석 → 그래프 IR | 유지 | ◐ `graph-architect` 보유, **출력 형식 결함** |
| **② BACKEND** | IR → 실행 스크립트·훅 번역 | 유지 | ❌ 번역기 0줄 |
| **③ DRIVER** | 완료까지 구동 (체크포인트·재개 포함) | 유지 | ◐ Claude Code Workflow 실적 316건 |
| **④ ARCHIVE** *(구 PGO)* | 실행 기록 → 결과 주석 아카이브 → ① 주입 | 유지, **비활성** | ❌ 조인 가능 아카이브 0건 |

## 단 판별 기준 — 벤더 카운트를 폐기한다

v4에서 **판정 도구를 교체한다.** 딥리서치는 벤더 공식문서 확인 횟수를 냈다(③ Runtime 9.5/10 · State 9.0 · Observability 9.0 · ⑥ Governance 4.0 · ② Compilation 1.5 · ④ Optimizer 0). 종합은 이 숫자로 ⑥을 격하했다.

**이 기준은 일관되게 적용되지 않았다.** 4.0을 격하하면서 1.5(②)와 0(④)은 유지한다. 같은 자를 대면 ②가 먼저 격하 대상이다.

따라서 벤더 카운트는 **참고 데이터로 강등**하고, 판정은 아래 하나로 한다.

> **단(stage)의 정의: 앞 단의 산출물을 받아 뒷 단의 입력을 만드는가.**

| 후보 | 입력 → 출력 | 판정 |
|---|---|---|
| ① | 프로젝트 → IR | ✅ 단 |
| ② | IR → 실행 스크립트·훅 | ✅ 단 |
| ③ | 스크립트 → 실행 + 실행기록 | ✅ 단 |
| ④ | 실행기록 → 아카이브 → ① 주입 | ✅ 단 (되먹임 간선) |
| **Observability** | 모든 단이 부산물 방출, **다음 단에 넘기는 것 없음** | ❌ 횡단 관심사 |
| **Governance** | 실행 경로상의 **지점들**, 순서 있는 단계 아님 | ❌ 횡단 관심사 |
| **State/Memory** | ③의 **존립 조건**, ③과 병렬인 축 아님 | ❌ ③에 흡수 |

`gcc`로 옮기면 Observability는 `-g` 플래그와 DWARF 섹션이지 패스가 아니다.

### 이것은 v1의 6 Layer 재현인가 — 기각 근거

**그렇다. 그래서 기각한다.** 반증 조사 원문:

> *"v1의 '6 Layer'가 OS 은유 때문에 부풀었던 것과 실질적으로 같은 실패 모드 — 이번엔 은유가 '엔터프라이즈 컨트롤 플레인'으로 바뀌었을 뿐이다. 계층 수가 6으로 같아지는 게 우연이 아니다."*

메커니즘이 동일하다: 큰 은유 채택 → 은유가 딸려오는 관심사를 전부 박스로 승격 → 6개.

**단, "늘리지 않는다"가 "무시한다"는 아니다.** 셋 다 새 박스 없이 기존 단의 구체 산출물로 환원했고, 환원 결과가 전부 숫자 게이트로 떨어진다:

| 횡단 관심사 | 환원처 | 게이트 |
|---|---|---|
| Observability | ③의 JSONL 산출물 규약 + ④의 조인 계약 | **G5** |
| Governance | ①IR의 policy 블록 → ②의 훅 출력 타깃 → ③의 집행 | **G6** |
| State/Memory | ③의 완료 조건 | **G7** |

환원 가능성이 6단 불필요의 증거이고, 환원 결과가 게이트로 떨어지는 것이 실체가 사라지지 않았다는 증거다.

## 각 단 상세

### ① FRONTEND — 유지, 산출 의무 2개 신설

`graph-architect` 실측 결과: **semantic은 이미 강제되나 syntax가 사람용뿐이다.**
SKILL.md 절대규칙 1(DEFINED NOT GUESSED)과 Step 4·UP-CONTRACT가 노드·엣지·숫자게이트·상태필드·재시도한도·휴먼게이트를 전부 요구하지만, 산출물은 **마크다운 표 + ASCII 아트**이고 JSON/YAML 산출 지시가 **0건**이다.

신설 의무 2개:

1. **기계 판독 IR 블록** — 필수 필드: 노드 id, 엣지, `gate{field,op,threshold}`, state 필드 목록, `retry.max`, `human_gate`, `policy`, `graph.spec.hash`, `graph.spec.version`, `project.fingerprint`
2. **policy 블록** — 노드별 `allowed_tools` / `requires_approval` / `budget{tokens,iterations,wall_clock}` / `reversible` / `gate.ground_truth`

⚠️ **v4가 새로 만드는 실패 모드**: 마크다운과 JSON 두 표현이 공존하면 사람이 마크다운만 고치고 JSON은 안 고치는 순간 ②가 **승인되지 않은 그래프를 컴파일**한다. 동기화 규칙을 G0에 포함시킨다 — JSON을 정본으로 하고 마크다운은 JSON에서 렌더링한다.

**각주**: ①의 능력 일부는 Avalon 자산이 아니라 **하네스 자산**이다. Claude Code는 Plan 서브에이전트를 내장 출하하며 `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1`로 끌 수 있다. 또한 OpenAI Agents SDK는 그래프/상태기계를 **의도적으로 거부**한다 — ①은 표준이 아니라 베팅이다.

### ② BACKEND — 유지, "갭" 표기 삭제

갭이 아니라 붐비는 전장이다. 선행 사례 9건: Compiled AI(2604.05150) · PayPal 선언적 DSL(2512.19769) · PlanCompiler(2604.13092) · SPL+splc(2607.07727) · One-Shot Agentic Compilation(2604.09718) · AgentSPEX(2604.13346) · Agint(2511.19635) · **gh-aw**(프로덕션) · **BAML**(프로덕션).

**불변식 INV-1 (신설)**
> LLM은 결정론 경계 **상류(①)에만** 둔다. ②는 LLM-free 순수 함수다.

출력 타깃: Claude Code Workflow 스크립트(`.claude/workflows/*.js`) · **훅(`settings.json`)** · bkit 재사용 노드.

⚠️ **미조사 영역 (v4에서 해소되지 않음)**: 훅은 전역 `settings.json`에 산다. 프로젝트별 그래프가 전역 설정을 쓸 때 (a) 프로젝트 A 정책이 B 세션에 새는가 (b) 동시 실행 시 충돌 (c) Avalon 없이 CC를 쓸 때 잔여 훅 제거 — **셋 다 조사 0건**. ② 착수 전 선결 과제.

### ③ DRIVER — 유지, 호스트 확정

**bkit `sprint-orchestrator` 일반화는 기각한다.** 8-phase enum · 전이 인접행렬 · `ACTIVE_GATES_BY_PHASE`가 전부 `Object.freeze`이고 `sprint-paths.js` 헤더가 *"Frozen - extension requires explicit code change"* 라고 못 박았다. 결정적으로 `.bkit/state/sprints` 디렉터리가 전 드라이브 **0건** — 완주 이력 자체가 없다.

**조립 기반은 Claude Code Workflow로 확정한다.** 실측: `wf_*.json` **316건**, completed 306 / failed 5 / killed 5 → **완주율 96.84%**.

> ⚠️ **증거 기준 비대칭 기록**: bkit 기각에는 "이력 0"을, Workflow 채택에는 "실행 316건"을 썼다. 그러나 316건은 리뷰·검증 워크플로 실행 이력이지 **임의 그래프 구동 이력이 아니다**. Workflow도 이 용도로는 미검증이다. 채택 근거는 "검증됐다"가 아니라 "동결되지 않았다"이다.

**흡수 항목** — State/Memory를 이 단의 완료 조건으로 흡수:
- 체크포인트·재개 (LangGraph checkpointer · Temporal Event History · MS AF Checkpoints 9/10 확인)
- 휴먼 게이트는 pass/fail이 아니라 **디스크에 직렬화되는 지속 가능한 일시정지**
- 게이트 판정은 에이전트 자기보고가 아니라 실측 상태를 읽는 술어 `g(노드, 산출물, 실측_상태)`

**알려진 고장**: `agent-state.json` 팀메이트 7명 전원 `status=spawning` 고착, `currentTask`/`taskId`/`progress` 전부 null.

### ④ ARCHIVE — 유지하되 **비활성**, 개칭

구 PGO. **이름을 폐기한다.** Go 공식 문서 기준 진짜 PGO는 의미 보존·무라벨·"프로파일이 틀려도 느려지지 않음"이라는 실패 하한을 갖는데, 에이전트 그래프 최적화는 **셋 다 위반**한다. 이름이 잘못된 안전 직관을 수입한다. 계승할 것은 프로파일 신선도 규율뿐이다.

**야심 축소**: "토폴로지 자동 재설계" → "(그래프 IR, 실행 결과, 실패 지점, 비용) 튜플 아카이브 + ① 주입".
프로덕션 트레이스로 토폴로지를 진화시킨 유일 사례 APEX(2606.15363)조차 *"Layer 3의 토폴로지 스코어링은 실제 task 완료율이 아니라 손으로 만든 구조적 휴리스틱"* 이라 자백했고, 검증 규모는 에이전트 1개·114 태스크·18일이다.

**선행조건 정정**: Observability가 아니라 **Evaluation**(판정 메트릭 + 케이스)이다.

> **비활성 판정**: Evaluation 자산이 0건이므로 ④는 현재 **단으로 존재하되 작동하지 않는다.** G8 충족 전까지 구현하지 않는다.
> **상충 기록**: `refute-5stage`는 ④를 단이 아니라 **되먹임 간선**으로 본다. 비평도 "Evaluation이 선행조건이라는 사실은 ④를 더 어렵게 만든다"며 이 견해를 지지한다. v4는 단으로 유지하되 이 이견을 미해결로 남긴다.

```

**부트스트랩 경로 (명시)**: 초기 아카이브는 0건이므로 ④는 비활성이다. ①의 기본 동작은 **매번 신규 설계**를 유지한다. 아카이브 조회를 기본으로 뒤집는 것은 G8 충족(≥10건) 이후의 별도 결정으로 미룬다.

> 종합은 ①의 기본 동작을 "아카이브 조회 후 미스일 때만 신규 설계"로 뒤집자고 제안했다(arXiv 2601.11147: 토큰 83% 절감, 성능 -0.61%). **v4는 이를 채택하지 않는다.** 이유 둘: (1) 아카이브 0건에서 조회는 항상 미스이므로 최소 10건을 쌓을 때까지 실효가 0이고, 그 10건은 뒤집기 **이전** 모드로만 만들 수 있다 — 명세가 자기 기본 동작을 도달 불가로 만든다. (2) 해당 논문은 벤치마크 태스크 대상이며 "프로젝트 개발 프로세스 그래프"로의 전이 근거가 없다.

## 차별점 — 폐기

**「자동 설계」는 차별점이 아니다.** 명세·대외 문구에서 삭제한다. *"선행연구 없음"*, *"경쟁 제품은 전부 사람이 그래프를 만든다"*, *"아무도 안 한다"* 류 표현을 v4 어디에도 남기지 않는다.

반례 24건 이상. 대표:

| 반례 | 내용 |
|---|---|
| **Blitzy** | 코드베이스 역공학 → 지식그래프 → bespoke agent plan → 3,000+ 에이전트 자율 구동. 2026-05 $200M 조달, 밸류 $1.4B. **①②③ 통째 상용화** |
| **CodePlan** (MSR, ACM PACMSE 2024) | 리포 의존성 + change-may-impact → plan graph → 빌드 통과까지 구동. 6개 리포 중 5개 통과(베이스라인 0) |
| **ADAS / AFlow / MaAS** | ICLR·ICML 정식 논문. 그래프 자동 설계 + 아카이브 축적 루프가 이미 정량 평가됨 |
| **AWS Kiro · GitHub Spec Kit** | 코드베이스 → requirements/design/tasks → 의존성 그래프 → wave 병렬. Spec Kit은 CC 포함 30+ 하네스 위에서 동작 |
| **Claude Code 내장 Plan** | 하네스 **기본 기능**. `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1`로 끌 수 있음 |
| **barkain/claude-code-workflow-orchestration** | 무료 CC 플러그인. 태스크 분해 → 의존성 분석 → wave 병렬 → 검증 에이전트 |
| **GitLab Auto DevOps** (2018~) | 언어·프레임워크 자동 감지 → 파이프라인 생성 → 완주. **LLM 이전에 이미 8년 된 개념** |

### 반례를 찾지 못한 형태 — 대외 주장으로 쓰지 않는다

두 가지가 남았으나 **차별점으로 승격하지 않는다.**

- **H1 (배치)** — 전용 플랫폼이나 CI 벤더에 종속되지 않고 사용자가 이미 쓰는 하네스 안에서 스킬 호출만으로 동작
- **H2 (층위)** — 단건 이슈 구현 계획이나 빌드 DAG가 아니라 **개발 프로세스 그래프 자체**를 프로젝트마다 다르게 설계하고 그 하네스의 스크립트·훅으로 컴파일

**승격 조건을 삭제한다.** 종합이 제시한 조건 (a) *"사람이 짠 그래프 대비 완료율·재작업률·소요시간 측정"* 은 통제 실험을 요구하는데, **1인이 같은 프로젝트를 두 번 하면 학습 효과로 오염된다 → 원리적으로 충족 불가**. 충족 불가 조건을 달아두면 H1/H2가 무기한 반증 불가 상태로 문서에 남아 사실상 차별점 주장의 약한 버전이 된다.

> **따라서 v4의 입장**: H1·H2는 *"조사 범위에서 반례를 찾지 못한 형태"* 로만 기록하고, 제품 가치 주장의 근거로 사용하지 않는다.

추가 약점(그대로 기재):
- H2 인접 영역은 이미 잠식 중 (barkain 플러그인, Workflow Builder 스킬)
- H1의 '이식성'은 현재 **Claude Code 1종에서만** 성립
- **이 틈에 수요가 있다는 근거는 조사 범위에서 발견되지 않았다**
- 경쟁 시장이 표방하는 가치는 자동 설계가 아니라 **명시적 제어·검사 가능성**(LangGraph 포지셔닝). 오픈소스 코딩 에이전트 오케스트레이터 9종 중 태스크 그래프 자동 생성은 1종뿐 — 역량 부재가 아니라 **의도적 설계 선택**일 가능성

## 숨은 전제 — 명시

**v4는 실사용 프로젝트 10~20개를 암묵 전제한다.**

G4d 골든 픽스처 10개(= 프로젝트 그래프 IR + 기대 컴파일 출력) + G8 아카이브 케이스 10건(= 완주한 실행 1건). 개인 사용자 1명에게 이것은 **수개월치**다.

> "4단 유지 = 구조를 안 늘렸다"와 대조하면 실질 범위는 v3보다 **훨씬 크다.** 늘어난 것: (a) ①의 산출 의무 2개 (b) ③의 완료 조건 3개 (c) 게이트 1개 → 9개 (d) 훅 격리 모델 선결 조사. 단을 늘렸다면 이 실질 작업이 새 박스 뒤로 숨었을 것이다 — **그게 v1에서 실제로 일어난 일이다.**
