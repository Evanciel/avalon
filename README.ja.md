## なぜ存在するのか

このプロジェクトは、小さな嘘から始まりました — AIエージェントが毎日、悪気なくついている種類の嘘です。

あるエージェントに複数ステップの仕事を渡し、任せておきました。計画は上手で、よく働き、こう報告してきました: **「完了しました — すべて通っています」**。説得力がありました。そして間違ってもいました。1つのステップは静かに諦められ、1つの検査は静かに飛ばされ、ループの中の何ひとつ、それを口にする理由を持っていなかったのです。

わざと嘘をついた者はいません。問題は構造にあります: **仕事をする者と採点する者が同じモデルなのです。** 自分の答案を自分で採点する学生は、悪意がなくてもAを付けてしまいます — そして夜通し無人で回り、緑に見えるまでリトライするエージェントは、一晩中喜んで自分を納得させ続けます。

<img src="images/who-judges.svg" alt="Avalonなしではエージェントが自分の点数を書く。Avalonではエージェントが測定値を出し、決定的なツールが判定する。" width="100%" />

解決策は古くて退屈で、だからこそ効きます: **判定を外に出す。** 作業を始める前に、計画をグラフとして描きます — ノードはやること、エッジは順序、ゲートは**数字だけ**で書かれた合格条件です。判定は小さな決定的ツール群が下します。ツールはLLMを呼ばないので、同じグラフには必ず同じ判定が返ります。仕事は今まで通りエージェントが全部やります — 自分を採点する権利だけを失うのです。

このリポジトリのルールは、どれもホワイトボードの上で設計されたものではありません。すべて、このプロジェクト自身の開発中に実際にすり抜けたバグから生まれました — 5件、それぞれが今は回帰テストに支えられたルールになっています:

<img src="images/scars.svg" alt="5つの実バグが5つのルールになった: 絶対に失敗できない検査、一度も使われなかった測定値、目隠しでコンパイルされたエージェント、黙って捨てられた承認、一度も存在しなかったフック" width="100%" />

(全部の顛末は[ルールが生まれた場所](#ルールが生まれた場所)にあります。プロジェクト当初の売り文句すら、自身の調査フェーズを生き延びられませんでした — [設計の紙の痕跡](#設計の紙の痕跡)参照。)

**Avalonを使うべきとき:** エージェントに大きな仕事を任せるとき(4ファイル以上、取り消しにくいステップ)、無人で回すとき、あるいは単に、証拠のない成功報告を信じられなくなったとき。1〜2ファイルの修正には**使わないでください** — 計画を描くコストが仕事より大きいなら、本末転倒です。

## Avalonがすること

<img src="images/pipeline.svg" alt="1 scaffoldはリポジトリを実測し、2 designは人間の判断、3 validateとcompileは4つの数字を検査し、4 runは追記専用の台帳とともに順序を強制する" width="100%" />

4ステップのうち2つは機械、1つはあなた(またはエージェント — ただし拒否権は機械が握ります)、1つは作業を見張る機械です。判断が入るのはステップ2 — ノードとゲートを何にするか決める瞬間 — だけ。その周りはすべて決定的に動きます。それが要点です: 判断は数字として一度だけ記録され、その後は誰も気分で再判定できません。

具体的に言うと、「ゲート」とはこういう1行のことです — そして*こういう1行だけ*です:

```jsonc
{ "field": "tests_failed", "op": "==", "threshold": 0 }
```

このフォーマットには「うまくいったか確認」と書く場所がありません。散文は合格条件ではないのです。

## 3ステップで始める

<img src="images/three-steps.svg" alt="3ステップ: 一度だけインストールし、普通の言葉で一行言い、最後に信号を読む" width="100%" />

### ① 一度だけインストール

```bash
git clone https://github.com/Evanciel/avalon ~/.claude/skills/avalon
```

Claude Codeでのインストールはこれで全部です — [SKILL.md](SKILL.md)のfrontmatter(`name: avalon`)がスキルの登録を担います。依存関係ゼロ、Node 18+。ツールは独立した `.mjs` ファイルで、あなたが自分で実行する必要はありません。(スキル抜きでツールだけ欲しい場合はnpmにもあります — `npm i avalon-skill`。リポジトリ自体をいじるなら: `git clone https://github.com/Evanciel/avalon && cd avalon && npm test`。)

### ② 一行言うだけ — 普通の言葉で

「グラフ」や「ゲート」が何かを知っている必要はありません。目標を言って、「本当に動くかの確認まで」を付けるだけです:

**ゼロから始めるとき** — まだ何も無いとき:

```text
avalonで進めて — うちのカフェのサイトをゼロから作って。
メニューページ、アクセス、お問い合わせフォーム。3つとも本当に動くかの確認まで。
```

**作りかけのものに足すとき** — そのプロジェクトのフォルダでClaude Codeを開いて頼むだけ。エージェントは手を付ける前に、すでにあるものを実測します:

```text
avalonで進めて — 作りかけのサイトに予約機能を追加して。
新しい予約が一覧に本当に載るかの確認まで。
```

**取り消しが怖い修正:**

```text
avalonで進めて — 決済まわりを直して。取り消せないことをする前には私に聞いて。
```

**寝ている間に任せる:**

```text
avalonで進めて — 寝ている間にこのリストを処理して。
ゲートが未達なら止まって — 取り繕わないで。
```

言い回しは自由です(「avalonでやって」「use the avalon procedure」…) — スキルのトリガーは名前です。数字・ゲート・グラフの設計はエージェントの仕事です。その代わりエージェントは、基準を**作業を始める前に分かる言葉で**見せなければなりません — 「送信を押したら保存されたメッセージが1件増えること、失敗した検査0件」のように。あなたは、それがあなたの思う*完成*かどうかを答えるだけです。

### ③ 信号を読む

最後に、4つの数字と、エージェントが偽造できない2つの欄が届きます:

- **緑4つ**(`coverage 1.00 · checks 6/6 · gate_loss 0 · hook_loss 0`) — 計画は健全で、変換で何も失われなかった。
- **`completed: true`** — すべてのゲートが実測値で通過した。
- **`abandoned: []`** — 空なら、何も諦められていません。リストに何か*ある*なら、それは「この部分はできなかった、証拠はこれ: 何を測り、バーはどこで、何回試したか」という意味です。

あなたの役割は全部で3手です: 開始前に基準リストを読んで「うん、それが『完成』で合ってる」と言う · *「このステップは取り消せません — 進めますか?」*と聞かれたら答える · 最後に信号を読む。

あなたが絶対に触らないもの: `graph.json`(エージェントが書く)、コマンド(エージェントが打つ)、しきい値(エージェントが提案 — あなたはそれがあなたの思う「完成」と合っているかを答えるだけ)。

### Claudeだけではない

ハーネスにClaude専用のものはありません — ツールは普通のNode CLIで、APIキーもベンダー呼び出しもなし。シェルコマンドを実行できるエージェントなら、どれでもこの手順を指させます:

```text
https://github.com/Evanciel/avalon をクローンして SKILL.md を読み、
その手順どおりにこのタスクを進めて: <あなたのタスク>
```

どのエージェントも同じ扱いを受けます: バリデータがグラフ草案に拒否権を行使し、ランナーが近道を拒否し、コンパイルされた `completed` フラグはエージェントの意見を無視します。そしてAIが全くいなくても、ランナーCLIは動きます — 人間用の規律チェックリストとして。

## 実行はこう見える

<img src="images/where-it-sits.svg" alt="あなたが一行の目標を渡すと、エージェントがリポジトリで働き、「完了しました」はAvalonのゲートを通ってしかあなたに届かない" width="100%" />

AvalonはAIエージェントを置き換えません — エージェントの「完了しました」とあなたの信頼のあいだに割り込みます。仕事は今まで通りエージェントが全部やり、その主張があなたに届く途中でゲートを通るだけです。

あなたが打った一行から、追加の指示なしで:

<img src="images/session-flow.svg" alt="実際のセッション: 一行渡すとエージェントが実測・設計し、ツールが判定し、未達ゲートはループバックし、不可逆ステップで承認を求め、最終報告にcompleted trueと空のabandonedが載る" width="100%" />

1. エージェントが `scaffold` を回し、グラフの草案を描き、何かをする前に4つの数字を見せます。
2. ノードを1つずつ進めて測定値を提出し、ツールが合否を答えます。
3. 不可逆ノードで止まってあなたに尋ねます — この停止は礼儀ではなく、出力にコンパイルされたものです。
4. 最終報告に `completed` と `abandoned[]` の証拠リストが載ります — エージェントが偽造できない2つの欄です。

失敗も含めた実際のセッションが見たいですか? 下の[チュートリアル](#チュートリアル-実際に1回回す)が一部始終をそのまま再生します。

## 保証

| 約束 | 守り方 |
|---|---|
| 偽の成功が不可能 | ゲートを飛ばした実行は自分を成功と報告する方法がない — コンパイル産物を実際に実行するテストが証明する |
| 諦めは証拠を残す | 試行回数と実測値が記録される。「まあ十分だろう」は存在しない |
| 判定がぶれない | 判定ツールはLLMを呼ばない。同じグラフなら同じ判定 — 気分も説得も通じない |
| 検査そのものが監査される | 機械強制されるすべての検査は、自分が失敗*できる*ことを証明しなければならない — 既知の壊れた入力に向けて赤くならなければ、インストールは拒否される |
| 記録は黙って書き換えられない | すべての測定は直前の行とハッシュチェーンで結ばれる。過去の行を書き換え・削除・並べ替えれば、人間が確認するまで全コマンドが拒否する |

### 諦めは成功ではない

<img src="images/abandon.svg" alt="リトライを使い切ったゲートは証拠をabandoned[]に残し、そのリストが空でない限り最終のcompletedは強制的にfalseになる" width="100%" />

ゲートが `on_exhaust: partial` でリトライを使い切ると、ワークフローは前へ進みます — ただし `{gate, node, field, op, threshold, measured, attempts}` を `abandoned[]` リストに記録し、そのリストが空でない限り最終の `completed` フラグは**強制的にfalse**になります。ゲートを飛ばした実行が自分を成功と報告する方法はありません。実行意味論のテストが、コンパイル出力を実際に実行してこれを固定しています。

### 仕様はインストールではない

<img src="images/stop-hook.svg" alt="エージェントがターンを終えようとすると、hooks-gateがすべてのcheckを回す: 全部グリーンならターンが終わり、1つでも赤ならexit 2でブロックされ未達ゲートがモデルに返される" width="100%" />

コンパイラは `build/hooks.json` — ゲートごとのcheckコマンドとexitコード契約 — を出力し、意図的にそこで止まります。インストールは別のツールが、別の人間の承認の下で行います。いったんインストールされれば、ゲートが赤い間、セッションは文字通りターンを終えられません。自動インストールは今も禁止です: 自分をセッションの強制レイヤーに黙って配線するツールこそ、このプロジェクトが防ぐために存在する種類の、説明のつかない魔法だからです。インストールされるまで仕様は何もブロックしません — そして完了報告には、その事実をこの言葉のまま書くことが求められます。

### すべてのcheckは失敗できることを証明する

*赤くなれない*checkの緑のチェックマークは、強制ではなく飾りです。そこでフック項目には `probe` を宣言できます — 同じオラクルを既知の壊れた入力に向けたもので、そこでは**必ず**exit非ゼロにならなければなりません。インストーラは、何かをインストールする前に宣言済みプローブを全部回します。exit 0 のプローブは「失敗できないcheck」をその場で実証したことになり、インストールは拒否されます:

```text
$ node tools/install-hooks.mjs graph.json build/hooks.json --yes
installer refused: probe refuted nothing — these checks cannot fail (or the probe never finished), so they enforce nothing:
  G1: probe exit 0 ← node -e "process.exit(0)"
```

(訳: インストーラ拒否: プローブが何も反証しなかった — このcheckは失敗できず、何も強制しない。)

健全な計画はゲートごとに反対証拠を印字します:

```text
  probe   G0  exit 1 ✅ (the oracle can fail)
  probe   G0b  exit 1 ✅ (the oracle can fail)
  probe   G4c  exit 1 ✅ (the oracle can fail)
```

この3行はこのリポジトリ自身のゲートのものです — それぞれ、拒否しなければならないコミット済みの壊れたフィクスチャ([tools/fixtures/](tools/fixtures/))に向けられています。

### 証拠は自分自身を守る

受理された測定はすべて追記専用の台帳に入り、台帳は**ハッシュチェーン**です: 各行が直前の行のハッシュを持ち、状態ファイルがチェーンの先頭を固定します。以下は、記録済みの測定値が後から書き換えられたときに実際に起きたことです — `verify` だけでなく、全コマンドが拒否します:

```text
$ node tools/run.mjs graph.json next
🔴 ledger chain broken — refusing every command:
  line 3: h mismatch — the line was edited
  the ledger is the evidence layer; a run on tampered evidence proves nothing.
  → inspect the ledger, archive it elsewhere, remove it, then re-init
```

(訳: 台帳チェーンが壊れた — 全コマンドを拒否。3行目の `h` が不一致 = 行が書き換えられた。)

チェーンが住むコードにも、ここにも正直に書いておきます: これは改竄の*証拠(tamper-evident)*であって、改竄の*不可能化(tamper-proof)*ではありません — [正直な限界](#正直な限界)参照。

## 内部構造

ここから下は、機構そのものを見たい読者のためのものです。使いたいだけなら、もう十分に知っています — 上の3ステップがユーザーマニュアルの全部です。

### ハーネスに何が入っているか

| 部品 | やること |
|---|---|
| **グラフ (JSON IR)** | 計画そのもの。ゲートは `フィールド + 演算子 + 数字` — 「うまくいったか確認」のような文章を書く欄がそもそも無い |
| **バリデータ** | 必須フィールド全数検査(G0) + 静的検査6種 + 記述式ゲートを表現の段階で拒否するスキーマ |
| **コンパイラ** | グラフをマルチエージェントのワークフロー実行コードに変換。ゲートが1つでも変換から漏れたら拒否する (`gate_loss`) |
| **ランナー** | 実行時に順序を強制。順番でないノードは開始できず、測定なしでは完了できず、すべての測定は追記専用の台帳に残る |
| **フック仕様 + インストーラ** | ゲートをセッションの**外**からも強制できるよう `build/hooks.json` を出力し、承認ゲート付きのインストーラがプロジェクトのsettingsにStopフックとして配線する。コマンドのない宣言は `hook_loss` が捕まえる |
| **スキャフォールド** | 対象リポジトリを実測し、すでに検証を通るスケルトンを生成 — 緑から始めて緑を保つ |

### 4ステージ構成

Avalonは4つのステージとして設計されており、このリポジトリのツールがその実装です:

| ステージ | 役割 | 実装 |
|---|---|---|
| **① FRONTEND** | 宣言 — リポジトリを実測してIRを書く | `scaffold.mjs` + あなたの判断、拒否権は `validate.mjs` |
| **② BACKEND** | コンパイル — 無損失のIR→実行コード変換、さもなくば拒否 | `compile.mjs` (`gate_loss`・`hook_loss`・承認停止・フック仕様) |
| **③ DRIVER** | 実行 — 数字のゲートの下で完了まで駆動 | `run.mjs`、またはオーケストレーションホストで回るコンパイル産物 |
| **④ ARCHIVE** | 蓄積 — 終わった実行が事例となり設計に還流 | **意図的に休眠** — 前提条件(敵対的入力への脅威モデル)が整うまでオフのままです。まだ安全でないステージは中途半端に回さず、休眠と宣言します |

ステージの境界こそが荷重を受ける部分です: 判断が入るのは①だけ、②は無損失か拒否か、③は実行するが判定しない、④はまだ存在を許されていない。境界ごとに少なくとも1つの傷跡があります([ルールが生まれた場所](#ルールが生まれた場所)参照)。

### 回し方は3通り

**① ワンショット、スキルとして — 本来の使い方。** 目標を伝えれば、残りはエージェントがやります:

1. 対象リポジトリに `scaffold` をかけて実測する。
2. 仕事をノードに分割し、ゲートを書く。ここが判断のステップ — 草案はエージェントが書き、拒否権はバリデータが握る。
3. スタンプ → 検証 → コンパイルで[4つの数字](#4つの数字)を緑にする。
4. コンパイルされたワークフローを実行する: ノードごとにサブエージェント1つ、引き継ぎはすべて数字のゲートを通し、グラフが終わるまで。

完了まで自走しますが、例外が2つあり、それこそが要点です: 不可逆なステップは止まって人間の承認を待ち、諦めたゲートは `abandoned[]` に残ります — エージェントが「まあ十分だろう」を黙って決めることはできません。

**② コンパイルされたワークフロー。** `compile.mjs` はグラフをエージェントオーケストレーションホスト用のワークフロースクリプトに変換します(ノードごとに `agent()` 呼び出し1つ、ファンアウトは `parallel()`)。停止地点からの再開と、特定の不可逆ノードの事前承認をサポートします:

```
Workflow({ scriptPath: "build/graph.workflow.js",
           args: { resume_from, resume_state, resume_loops, approved: ["<node-id>"] } })
```

`policy.requires_approval: true` のノードは、idが `approved` に無ければ**実行前に止まります**。デフォルトは空集合 — 回帰テストがそれを固定しているので、承認ゲートがいつの間にか無力化することはありません。

**③ ランナーCLI — 手動またはエージェント直接駆動。** セッションがサブエージェントを立てず、ノードを直接回す場合:

```bash
node tools/run.mjs graph.json init            # create state (after editing the graph: init --force)
node tools/run.mjs graph.json next            # what can be worked on right now
node tools/run.mjs graph.json status          # whole picture, including gates that never ran
node tools/run.mjs graph.json start <node>    # refused if the node isn't in the frontier
node tools/run.mjs graph.json measure <field> <value> [note]
node tools/run.mjs graph.json done <node>     # the tool decides pass/fail, not you
node tools/run.mjs graph.json verify          # ledger hash-chain check (tamper / truncation)
node tools/run.mjs graph.json abort           # cancel the active node
node tools/run.mjs graph.json lint            # OR-trap check (2+ gates on one node)
```

すべてのコマンドに機械可読出力 `--json` があります。ランナーは実質「やらせないことのリスト」で、4つの不変条件(INV-1〜4、[run.mjs](tools/run.mjs))から来ています:

| こうすると | ランナーの答え |
|---|---|
| 順番でないノードを `start` | 拒否 — 代わりに今始められるノードを教えてくれる |
| 今回の訪問の測定なしで `done` | 拒否 — 古い測定値は持ち越されず、古い緑でリトライを通過できない |
| グラフで宣言していないフィールドを `measure` | 拒否 — 宣言のないフィールドを測るのは、手続きを踏んだ当てずっぽうにすぎない |
| `init` 後にグラフを直して続行 | **STALE** 表示 — 状態は自分がどのグラフハッシュから生まれたか覚えている |
| ゲートを `max_retry` 回より多く失敗 | **停止** — 実行が止まり、決定が人間に渡る |

受理された測定はすべて台帳に追記されます。台帳の中身は決して書き換えられません — `init --force` でさえ状態を捨てるだけで台帳は残します。そして台帳は自分自身を守ります: [証拠は自分自身を守る](#証拠は自分自身を守る)参照。

ツールのメッセージは既定で英語です。韓国語のシステムロケール(または `AVALON_LANG=ko`)で韓国語に切り替わります(日本語は未対応)。ビルド成果物は常に英語です — バイトがハッシュされるため、環境に依存してはならないからです。

### チュートリアル: 実際に1回回す

以下はすべて実際に起きたことです — コマンドと出力はライブセッションからそのまま、失敗も含めて。(これらの出力は韓国語メッセージ時代に採取されました — ツールは現在既定で英語、`AVALON_LANG=ko` で韓国語です。ここでは英語訳で示し、必要な箇所に日本語の説明を添えます。)

小さなNodeプロジェクト `my-api` があり、エージェントに検索エンドポイントを追加してテストを通させたいとします。

**1. スキャフォールド。** リポジトリとタスク一行を渡します:

```bash
node tools/scaffold.mjs ../my-api "add a search API and make the tests pass" ../my-api/graph.json
```

すでに検証を通る3ノードのスケルトン(`survey → check → review`)が出ます。スタックと規模は実測済み、ハッシュも2つ刻印済みです。

**2. 設計。** プレースホルダを本物の計画に置き換えます — ノード3つ、ゲート1つ:

```jsonc
"state": [{ "field": "tests_failed", "type": "int", "unit": "count" }],
"gates": [{
  "id": "G1", "field": "tests_failed", "op": "==", "threshold": 0,
  "on_fail": { "goto": "implement", "max_retry": 2 },
  "ground_truth": "measured",
  "threshold_source": "the whole suite must pass — partial passing is not a ship criterion"
}],
"edges": [
  { "from": "implement", "to": "test", "when": "always"       },
  { "from": "test", "to": "implement", "when": "gate:G1:fail" },
  { "from": "test", "to": "ship",      "when": "gate:G1:pass" }
]
```

**3. スタンプと検証。** このチュートリアルを書きながら実際にミスをしました — ノード名を変えて `graph.entry` を忘れたのです。バリデータが実行前に捕まえました:

```
$ node tools/validate.mjs graph.json
  FAIL  reachability
         ↳ graph.entry 'survey': no such node
  static_checks_passed  5/6      G4c FAIL
```

(訳: 到達可能性がFAIL — `graph.entry 'survey'`: そんなノードは無い。)

entryを直し、再スタンプ(`hash.mjs --write`)、再検証 → `6/6`、カバレッジ `1.00`。

**4. コンパイル。**

```
$ node tools/compile.mjs graph.json build/graph.workflow.js
  gate_loss  0      PASS
  hook_loss  0      PASS
  compiled → build/graph.workflow.js
  hooks    → build/hooks.json
```

**5. 実行。** ランナーのセッションをそのまま(注釈のみ追加):

```
$ run.mjs graph.json init
$ run.mjs graph.json start ship          # trying to skip ahead
🔴 not in the frontier: ship — you can start: implement

$ run.mjs graph.json start implement     # ok — do the actual work here
$ run.mjs graph.json done implement      # opens: test

$ run.mjs graph.json start test
$ run.mjs graph.json done test           # forgot to measure
🔴 cannot judge the gate — no measurement this visit:
   G1: tests_failed was never measured

$ run.mjs graph.json measure tests_failed 3 "npm test: 3 failing"
$ run.mjs graph.json done test
🔴 G1: tests_failed=3 == 0 → fail        # loops back to implement (attempt 1/2)

# ...fix the code, come back through implement → test...
$ run.mjs graph.json measure tests_failed 0 "npm test: all green"
$ run.mjs graph.json done test
🟢 G1: tests_failed=0 == 0 → pass

$ run.mjs graph.json status
  ▶ ship  (human/manual)  ⏸ waiting for a person   # irreversible → a human takes the exit
```

(訳: 順番を飛ばした `start ship` は「フロンティアに無い」と拒否 · 測定を忘れた `done` は「ゲートを判定できない」 · `tests_failed=3` はfailで `implement` に戻り(リトライ 1/2)、`0` でpass · 最後の `ship` は不可逆なので人間待ち。)

起きなかったことに注目してください: 誰もエージェントに「終わった?」と聞いていません。`3` を報告すればツールがfailと言い、`0` を報告すればpassと言った — それだけです。

**6. セッションの外からも強制する(任意)。** コンパイルはすでに `build/hooks.json` を出しています。インストールするとゲートがセッションのStopフックに配線されます — ただしインストーラは、明示的な承認なしには動きません:

```
$ node tools/install-hooks.mjs graph.json build/hooks.json
Install plan (nothing written yet):
  target  .claude/settings.json
  hook    Stop → node tools/hooks-gate.mjs graph.json build/hooks.json
  gates   G1
approval required — after user confirmation: same command with --yes    (exit 3)
```

(訳: インストール計画 — まだ何も書いていない。承認が必要 — ユーザー確認後、同じコマンドに `--yes`。)

`--yes` でインストールされ、それ以降ゲートが赤い間はセッションが文字通りターンを終えられません(`hooks-gate.mjs` がexit 2を返し、停止をブロックします)。インストール後にグラフが変わるとゲートはSTALEを報告し、古いルールで通す代わりにブロックします — 再コンパイルと再インストールが解消経路です。削除はいつでも `--uninstall --yes` で。

### グラフのフォーマット

正本はJSONファイル1つです。構成要素:

**ノード** — やること。`kind` は `work`・`human`・`join`(`gate` というノードkindはv1.1にありましたが廃止 — ゲートは今やエッジの管轄です)。各ノードは `budget` と `retry.max` を持ち、不可逆なステップには `policy.requires_approval: true` を付けます — コンパイラがこれを本物の停止に変えます。

**エッジ** — 順序。`when` は `always` か `gate:<id>:pass` / `gate:<id>:fail` のどちらかです。語彙はこれで全部 — 「時々」はありません。

**ゲート** — 合格条件。JSONオブジェクト1つ、自由記述欄なし、寛大に解釈できる余地がどこにもありません:

```jsonc
{
  "id": "G1",
  "field": "tests_failed",          // must be declared in state[] — unknown fields are rejected
  "op": "==",                        // one of  ==  >=  <=  >  <
  "threshold": 0,
  "on_fail": { "goto": "fix", "max_retry": 2 },
  "ground_truth": "measured",        // measured | reported | human | assumed
  "threshold_source": "why this number — forces you to justify it once, in writing"
}
```

`max_retry: 0` は*停止*ではなく*分岐*です — 「失敗したらリトライせずあちらへ行く」(縮小リリースの経路、NO-GOレポート)。ただしリトライ0の分岐がすでに終わったノードへ戻るなら、それは予算のないループなので、ランナーは止まります。

`done` を打つと、ツールが `tests_failed` の最新測定値を読み、`== 0` を適用して合否を答えます。しきい値への異論は実行前にどうぞ。実行中に判定へ抗議する方法はありません。

**状態(state)** — 宣言された測定フィールドで、それぞれ型があります: `int`・`ratio`・`bool`・`enum`・`ref`・`text`。ゲートを掛けられるのは `int`/`ratio`/`bool` だけ — 散文にしきい値は掛けられないので、`enum`/`ref`/`text` はまずカウンタに派生させる必要があります。スキーマは単位の間違いも捕まえます。たとえば `ratio`(0〜1)のフィールドにパーセントのしきい値(90)を与えると、永遠に通らないゲートになる — 実際にあった話です。

**指紋(fingerprint)** — 対象リポジトリの実測事実(スタック、規模、マーカー)。`scaffold` が埋め、決して推測しません。規模は区間(`100-299` ファイル)で保存します — 正確な数は明日には違いますが、区間は真のままだからです。

**ホスト(host)** — 強制が住む場所: `state_file`(ランナーが状態を置く場所)、`enforced_by_hook`(どのゲートを外から機械強制するか、それぞれ `{ "gate": "G0", "check": "node tools/validate.mjs graph.json" }` の形 — コマンドのない宣言こそ `hook_loss` が数えるものです)、そして `produces`。

**スペックハッシュ** — `hash.mjs` がグラフのcanonical形(キー順は無関係、配列順は意味を持つ)にsha256を刻印します。下流のすべての産物がこのハッシュを持ちます。だからランナーは実行中に変わったグラフを検知でき(STALE)、フックは自分が強制するグラフと正確に照合されます。

**スキーマバージョニング** — `spec.version` が検証語彙を選びます。古いv1.1グラフはv1.1のルールで検証されます(回帰コーパスなので、拒否するとベースラインが消えます)。ただしv1.1は*実行不可*と印されます — 「どのリポジトリで」「何を」を書く欄が無いため、コンパイラが拒否します。検証を通ることと実行して安全なことは別の主張であり、ツールはこの2つを分けたままにします。

### 4つの数字

**実行前に4つの数字がすべて緑である必要があります:**

| | 合格条件 | 意味 |
|---|---|---|
| `ir_field_coverage` | 1.00 | 必須13フィールドがすべて埋まっている |
| `static_checks_passed` | 6/6 | グラフの構造に問題がない |
| `gate_loss` | 0 | 宣言したゲートがすべて実行コードに載った |
| `hook_loss` | 0 | 宣言したフックすべてに本物のコマンドが付いている |

lossが0でないなら、「宣言はあるが誰も強制しない」状態です。そのグラフは飾りであり、ツールが非ゼロのexitコードでそう言います。

### ツールを1つずつ

独立したファイル群で、相互の依存はimportだけ、どれもLLMを呼びません(INV-1)。決定的というのは文字通りの意味です: 同じ入力なら、同じバイトが出ます。

**`scaffold.mjs` — 推測ではなく実測。** 対象リポジトリを歩き(`node_modules`・`.git`・ビルド産物はスキップ、5万ファイルを這わないよう上限付き)、スタックを検出し、規模を区間化し、ハッシュを刻印し、**すでに検証を通る**グラフスケルトンを出します。ノードはプレースホルダです — そこは判断であり、あなたの仕事です。しかし高くつくボイラープレート(必須13フィールド、ハッシュ、retry/policyのデフォルト、必須のhumanノード1個)は機械が埋めます。緑から始めて緑を保つほうが、赤から始めて祈るより良いのです。

**`hash.mjs` — canonical JSON + sha256。** 正規化し(キー順は無関係、配列順は保存 — 意味を運ぶので)、ハッシュし、ハッシュフィールド自身を除いて `sha256:<64hex>` をグラフに刻印します。冪等です。3回回せば3回同じ結果。STALE検知とフック照合はすべてこの刻印に掛かっています。

**`validate.mjs` — G0 + 静的検査6種 + 意見のあるスキーマ。**

- **G0**: 必須13フィールドがすべて存在すること。部分的な充足は無意味なので、バーは1.00です。
- **静的検査6種**: ゲートは宣言済み状態フィールドのみ参照 · 不可逆ノードに承認あり · すべてのノードが到達可能 · すべての循環に上限あり(停止性) · すべてのノードに予算あり · すべてのエッジが実在ノードを指し `when` の形式が正しい。
- **スキーマレベルの拒否**(検査が走る前に): 記述式ゲート — `field/op/threshold` の代わりに散文を書いたゲートはそもそも表現できない · 未知の演算子 · ゲート不可の型へのゲート · booleanのしきい値 · `host.enforced_by_hook` からの幽霊ゲート参照 · 新しいグラフでの廃止語彙。
- **品質警告**(非致命): `scope`/`host` の欠落、`check` コマンドのないフック宣言。

**`render.mjs` — マークダウンは産物である。** JSONを読みやすいマークダウンに決定的にレンダリングします。`--check` は再レンダリングし、コミット済みの `graph.md` と**バイト単位**(sha256)で照合します — それがゲートG0bです。誰かがマークダウンを手で直せば検査が落ちます。文書は計画からずれることができません。文書とは、レンダリングされた計画そのものだからです。

**`compile.mjs` — 無損失の変換、さもなくば変換なし。** IRからワークフロースクリプトへの純関数です。内部では非決定性を禁止 — `Date` なし、`Math.random` なし、オブジェクトキーの巡回順への依存なし。出力するもの:

- ノードごとにサブエージェント呼び出し1つ。すべてのプロンプトに**共有コンテキストブロック**(指紋・target・task)を注入 — 実測事実が仕事と一緒に移動します;
- ノードに `always` エッジが複数あれば**並列ファンアウト**、枝は単一のjoinで合流;
- humanノードのゲートも保存(人間が測る `design_approved` もゲートであり、コメントではない);
- `requires_approval` ノードでの**承認停止**、`approved` 引数を尊重(デフォルト: 誰も承認されていない);
- **再開**サポート(`resume_from`・`resume_state`・`resume_loops`);
- **ABANDONED台帳**([前述](#諦めは成功ではない));
- `build/hooks.json` — フック強制ゲートごとに1エントリ: `{ gate, field, op, threshold, check, expect_exit: 0 }`、スペックハッシュでグラフと結合。

そして自分自身を監査します: IRのすべてのゲートが出力に現れなければならず(`gate_loss`)、宣言されたすべてのフックがコマンド付きで `hooks.json` に現れなければなりません(`hook_loss`)。どこかにlossがあれば → exit非ゼロ、どの産物も信頼されません。

**`run.mjs` — 実行者。** フロンティア規律、測定台帳、ゲート判定、STALE検知、停止時の人間への引き渡し。上の[回し方は3通り](#回し方は3通り)で説明した通りです。ファイル冒頭の4つの不変条件が契約であり、自己試験は、その1つ1つが実際に噛みつくことを証明するために存在します。台帳のハッシュチェーン — そして改竄の下で起きる拒否 — は[証拠は自分自身を守る](#証拠は自分自身を守る)に示しました。

**`install-hooks.mjs` + `hooks-gate.mjs` — セッションを生き延びる強制。** インストーラは `build/hooks.json` を**プロジェクトの** `.claude/settings.json` にStopフックとして配線します。要点はその境界です: `--yes` なしには何も書かない(計画を印字してexit 3 — エージェントがユーザーの了承なしに `--yes` を付けてはなりません)、グローバルの `~/.claude` settingsは `--yes` があっても拒否、ハッシュが現在のグラフと合わない仕様は拒否、他人のフック項目は保存、再インストールは冪等。`--uninstall --yes` でいつでも外せます。

さらに、**何を承認したかそれ自体を刻印します**: 承認時点の `build/hooks.json` のバイトハッシュが、インストールされるコマンドにそのまま埋め込まれます(`--approved sha256:…`)。以後ファイルがどんな形であれ変われば、ゲートは**checkを1つも実行する前に**ブロックし、TAMPEREDと報告します — これがなければ、JSONファイル1つへの書き込み権限が、毎ターン終了時に任意のコマンドを自動実行させる権限と等しくなってしまいます。戻る道は再承認(`--yes` 再インストール)だけです。

そして、[すべてのcheckは失敗できることを証明する](#すべてのcheckは失敗できることを証明する)で示した反対証拠を要求します。プローブの無いフックもインストールは通ります(「未証明」と報告されるだけで、遡及的な破壊はありません)。`--status` はいつでも読み取り専用の診断を返します: インストール済みか否か、承認ピンが無事かTAMPEREDか、仕様が最新かSTALEか — checkを1つも実行せずに。

インストール後は、セッションがターンを終えようとするたびに `hooks-gate.mjs` が宣言済みcheckを全部回します: 全部通過 → exit 0、1つでも未達 → exit 2で停止をブロックし、未達ゲートをモデルに返します。グラフが変わればSTALEを報告してブロックします — 昨日のルールを黙って強制するくらいなら、止まるほうがましだからです。

### ルールが生まれた場所

これらは机上で設計されたものではありません。すべてのルールは実際にすり抜けたバグから生まれ、同じ*種類*のバグが繰り返されると番号が付きます:

| # | 何が起きたか | 今は何が防ぐか |
|---|---|---|
| 1 | 絶対に失敗できない検査があった — 別の検査がすでに強制する条件をもう一度尋ねていた | ループを実際に断つ条件へ検査を書き直した |
| 2 | プロジェクトの指紋を測定してIRに保存までしたのに、プロンプトには一文字も載らなかった | 共有コンテキストブロック + 回帰テスト |
| 3 | 「どのリポジトリで何を」を書く欄がIRに無かった — コンパイルされたエージェントは目隠しで開始した | `target`・`task` を必須化、無ければコンパイル拒否 |
| 4 | 承認必須の宣言が検証を通った後、コンパイラが黙って捨てた — 不可逆な `git push` が停止なしでコンパイルされた | 承認ゲートをコードに出力 + 回帰テスト |
| 5 | フック強制がIRに宣言され検査も全部緑だったのに、フックファイルは一度も存在しなかった | 宣言に実行可能なコマンドを必須で付け、その隙間を `hook_loss` が数える |

共通パターンは1つ: **宣言は検証され、その後捨てられる。** lossメトリクスは、この種のバグを見逃せなくするために存在します。

この最後の習慣がこのディレクトリ全体の要点です: 文書はAvalonが何であるかだけでなく、何になりかけて、それがなぜ間違いだったかまで記録しています。

### AvalonはAvalonの上で回る

リポジトリルートの [graph.json](graph.json) はサンプルではありません — Avalon自身の開発をAvalonが管理するグラフです。ノード7個(`frontend → validate → render_check → backend → compile_check → human_go → install_hooks`)、宣言済み状態フィールド6個、そしてゲート3個(G0・G0b・G4c)が `host.enforced_by_hook` で機械強制されます — それぞれ実際に検査するコマンドに加え、そのコマンドが失敗できることを証明するプローブ(コミット済みの壊れたフィクスチャ狙い)付きで。[graph.md](graph.md) はそのレンダリングで、G0bがバイト単位で検証します。

グラフの `guarantees` ブロックは、正直な限界リストの機械寄りの形です: `provides` は緑の実行が正確に何を証明するか、`excludes` は何を証明しないかを書きます。このリポジトリ自身のゲートが赤くなれば、CIが落ちます。

## テスト方法

`npm test` 1つで回る3つのスイート、合計158件:

- **[test.mjs](tools/test.mjs) (93件)** — スキーマとコンパイラの挙動、そして**実行意味論**: コンパイルされたワークフロー出力をスタブホストで実際に実行します。「abandonedが空でなければcompletedはfalse」のような主張が、断言ではなく実演されます。新顔は**指紋の弁別力**です — 同じリポジトリを2回実測すればバイトまで同じ指紋、別のリポジトリなら別の指紋にならなければなりません。実際のscaffold実行で測ります。指紋の弁別力は、このテストまで*未検証*の主張でした。デプロイ同期ゲートはランタイムファイル9個をインストール済みスキルのコピーとバイト照合し、リポジトリと配備物が静かにずれるのを防ぎます。
- **[run.selftest.mjs](tools/run.selftest.mjs) (41件)** — ランナーの拒否の壁を、壁の存在を証明する唯一の方法でテストします: *ガードを消せばスイートが赤くならなければならない。* 各テストは禁止された状況(フロンティア外のstart、測定なしのdone、グラフを直して続行)を構成し、ランナーが拒否したときだけ通ります。台帳チェーンのテストは本物の台帳を攻撃します — 過去の測定値を書き換え、末尾を切り詰め、チェーンを迂回して追記します — そして全コマンドが拒否して初めて通ります。
- **[install.selftest.mjs](tools/install.selftest.mjs) (24件)** — インストーラの境界を同じ方法で: `--yes` なしの書き込み禁止、グローバル拒否、古い仕様の拒否、他人のフック保存、冪等な再インストール、そしてゲートの未達・STALEブロック(exit 2)。3件はTOCTOU攻撃シナリオです: 承認の*後で* `build/hooks.json` を書き換え — checkを悪意あるコマンドに差し替え、グラフごと整合的に再生成までして — ゲートが**何も実行せずに**ブロックしたときだけ通ります(仕込んだコマンドが走らなかったことをマーカーファイルで証明)。残りはプローブの壁(失敗できないオラクルは飾りとして拒否)、`--status` が書かずに読むだけであること、そして既定言語が本当に英語であることを固定します。

CIはubuntuとwindowsで3つのスイートすべてを回します。改行は [.gitattributes](.gitattributes) でLFに固定しています — G0bはバイト単位のオラクルなので、CRLFのチェックアウトは厳密には別の文書になってしまうからです。

## 正直な限界

- ツールが証明するのは**宣言されたオラクル**だけです。checkコマンドが人間語の題名と同じ意味かどうかは、いまもあなたが見る必要があります。`probe` はこの隙間を狭めます — オラクルが失敗*できる*ことまでは証明します — が、閉じはしません。決定的ツールには閉じられません。
- `build/hooks.json` は仕様です。`install-hooks.mjs --yes`(人間承認のステップ)でインストールされるまで、何もブロックしません。
- エージェントノードが実行時に作る成果物は、コンパイル時には検証できません。
- 台帳チェーンは改竄の*証拠(tamper-evident)*であって*不可能化(tamper-proof)*ではありません: 書き換え・削除・切り詰めは捕まえますが、台帳と状態を一緒に整合的に書き換える者には敗れます。それを捕まえる外部アンカーは④ARCHIVEの仕事で、④は休眠中です。
- ツールのメッセージは既定で英語です(`AVALON_LANG=ko` で韓国語。日本語は未対応)。コードのコメントと [docs/graph/](docs/graph/) の設計史は韓国語です — 理由付けは文書化されていますが、まだ翻訳されていません。

完全な最新リストは、自己適用グラフの `guarantees` ブロックにあります。
