## どんな問題を解くのか

AIエージェントに大きな仕事を任せると、最後に「完了しました」と言います。問題は、そう言った側と確認した側が同じAIだという点です。試験を受けた学生が採点までやるようなもので、抜けがあっても誰も気づきません。

AIをループで回すとき(夜通しの自動作業、通るまでリトライ)、この問題はさらに大きくなります。判定基準がエージェントの外に無ければ、ループは自分を騙しながら気持ちよく回り続けます。

Avalonは順序をひっくり返します。作業を始める**前に**、計画をグラフとして描きます。ノードはやること、エッジは順序、ゲートは合格条件 — そしてゲートに書けるのは**数字だけ**です。判定は小さなツール群が下します。ツールはLLMを呼ばないので、同じグラフを入れれば必ず同じ答えが返ります。

<img src="images/who-judges.svg" alt="Avalonなしではエージェントが自分の点数を書く。Avalonではエージェントが測定値を出し、決定的なツールが判定する。" width="100%" />

仕事は今まで通りエージェントが全部やります — 自分を採点する権利だけを失うのです。

## 誰のためのものか

- **エージェントに大きな仕事を任せる人。** 4ファイル以上、複数モジュール、取り消しにくいステップが混ざる作業。仕事が大きいほど、「完了しました」が隠せる穴も大きくなります。
- **夜通し自動で回す人。** 無人ループ、通るまでリトライ。判定者がエージェントの外にいなければ、ループは自分を騙しながら朝を迎えます。
- **「完了しました」に火傷したことがある人。** 一度で十分ですよね。証拠のない成功報告を信じられなくなったすべての人へ。

1〜2ファイルの修正には使わないでください — 計画を描くコストが仕事より大きいなら本末転倒です。

**得られるもの:**

| 約束 | 守り方 |
|---|---|
| 偽の成功が不可能 | ゲートを飛ばした実行は自分を成功と報告する方法がありません — コンパイル産物を実際に実行するテストが証明します |
| 諦めが記録される | 試行回数と実測値が残ります。「まあ十分だろう」はありません |
| 判定がぶれない | 判定ツールはLLMを呼びません。同じグラフなら同じ判定 — 気分も説得も通じません |

## ハーネスに何が入っているか

| 部品 | やること |
|---|---|
| **グラフ (JSON IR)** | 計画そのもの。ゲートは `フィールド + 演算子 + 数字` — 「うまくいったか確認」のような文章を書く欄がそもそも無い |
| **バリデータ** | 必須フィールド全数検査(G0) + 静的検査6種 + 記述式ゲートを表現の段階で拒否するスキーマ |
| **コンパイラ** | グラフをマルチエージェントのワークフロー実行コードに変換。ゲートが1つでも変換から漏れたら拒否する (`gate_loss`) |
| **ランナー** | 実行時に順序を強制。順番でないノードは開始できず、測定なしでは完了できず、すべての測定は追記専用の台帳に残る |
| **フック仕様 + インストーラ** | ゲートをセッションの**外**からも強制できるよう `build/hooks.json` を出力し、承認ゲート付きのインストーラがプロジェクトのsettingsにStopフックとして配線する。コマンドのない宣言は `hook_loss` が捕まえる |
| **スキャフォールド** | 対象リポジトリを実測し、すでに検証を通るスケルトンを生成 — 緑から始めて緑を保つ |

## 4ステージ構成

Avalonは4つのステージとして設計されており、このリポジトリのツールがその実装です:

| ステージ | 役割 | 実装 |
|---|---|---|
| **① FRONTEND** | 宣言 — リポジトリを実測してIRを書く | `scaffold.mjs` + 人間/モデルの判断、拒否権は `validate.mjs` |
| **② BACKEND** | コンパイル — 無損失の変換、さもなくば拒否 | `compile.mjs` (`gate_loss`・`hook_loss`・承認停止・フック仕様) |
| **③ DRIVER** | 実行 — 数字のゲートの下で完了まで駆動 | `run.mjs`、またはオーケストレーションホストで回るコンパイル産物 |
| **④ ARCHIVE** | 蓄積 — 終わった実行が事例となり設計に還流 | **意図的に休眠** — 前提条件(敵対的入力への脅威モデル)が整うまでオフのままです。まだ安全でないステージは中途半端に回さず、休眠と宣言します |

ステージの境界こそが荷重を受ける部分です: 判断が入るのは①だけ、②は無損失か拒否か、③は実行するが判定しない、④はまだ存在を許されていない。境界ごとに少なくとも1つの傷跡があります([ルールが生まれた場所](#ルールが生まれた場所)参照)。

## 実行の流れ

<img src="images/pipeline.svg" alt="1 scaffoldはリポジトリを実測し、2 designは人間の判断、3 validateとcompileは4つの数字を検査し、4 runは順序を強制して台帳に記録する" width="100%" />

4ステップのうち2つは機械、1つはあなた、1つはあなたを見張る機械です。判断が入るのはステップ2 — ノードとゲートを何にするか決める瞬間 — だけ。その周りはすべて決定的に動きます。それが要点です。判断は数字として一度だけ記録され、その後は誰も気分で再判定できません。

## インストール

```bash
git clone https://github.com/Evanciel/avalon && cd avalon
npm test        # テスト158件、依存関係0、Node 18+
```

ツールチェーンだけ欲しい場合はnpmでも入手できます — `npm i avalon-skill`。スキル自体は上記の通り `~/.claude/skills` へのクローンでインストールします。

**Claude Codeのスキル**として使うには、スキルディレクトリにクローンするだけです — [SKILL.md](SKILL.md)のfrontmatter(`name: avalon`)が登録を担います:

```bash
git clone https://github.com/Evanciel/avalon ~/.claude/skills/avalon
```

あとは「avalonで進めて」のような一言で手順全体がロードされます。インストール手順も依存関係もありません — ツールは独立した `.mjs` ファイル6個です。

## 回し方は3通り

### ① ワンショット、スキルとして — 本来の使い方

目標を伝えれば、残りはエージェントがやります:

1. 対象リポジトリに `scaffold` をかけて実測する。
2. 仕事をノードに分割し、ゲートを書く。ここが判断のステップ — 草案はエージェントが書き、拒否権はバリデータが握る。
3. スタンプ → 検証 → コンパイルで[4つの数字](#4つの数字)を緑にする。
4. コンパイルされたワークフローを実行する: ノードごとにサブエージェント1つ、引き継ぎごとに数字のゲート、グラフが終わるまで。

完了まで自走しますが、例外が2つあり、それこそがこのスキルの存在理由です: 不可逆なステップは止まって人間の承認を待ち、諦めたゲートは `abandoned[]` に残る — エージェントが「まあ十分だろう」を黙って決めることはできません。

### ② コンパイルされたワークフロー

`compile.mjs` はグラフをエージェントオーケストレーションホスト用のワークフロースクリプトに変換します(ノードごとに `agent()` 呼び出し1つ、ファンアウトは `parallel()`)。停止地点からの再開と、特定の不可逆ノードの事前承認をサポートします:

```
Workflow({ scriptPath: "build/graph.workflow.js",
           args: { resume_from, resume_state, resume_loops, approved: ["<ノードid>"] } })
```

`policy.requires_approval: true` のノードは、idが `approved` に無ければ**実行前に止まります**。デフォルトは空集合 — 承認ゲートがいつの間にか無力化しないよう、回帰テストが固定しています。

### ③ ランナーCLI — 手動またはエージェント直接駆動

セッションがサブエージェントを立てず、ノードを直接回す場合:

```bash
node tools/run.mjs graph.json init            # 状態を生成(グラフを直した後は init --force)
node tools/run.mjs graph.json next            # 今できること
node tools/run.mjs graph.json status          # 全体像 + まだ回っていないゲートまで
node tools/run.mjs graph.json start <ノード>  # フロンティア外なら拒否
node tools/run.mjs graph.json measure <フィールド> <値> [メモ]
node tools/run.mjs graph.json done <ノード>   # 合否を決めるのはツール、あなたではない
node tools/run.mjs graph.json verify          # 台帳ハッシュチェーン検証(改竄・切り詰め)
node tools/run.mjs graph.json abort           # 進行中ノードの取り消し
node tools/run.mjs graph.json lint            # ORの罠検査(1ノードにゲート2個以上)
```

すべてのコマンドに機械可読出力 `--json` があります。ランナーは実質「やらせないことのリスト」で、4つの不変条件(INV-1〜4、[run.mjs](tools/run.mjs))から来ています:

| こうすると | ランナーの答え |
|---|---|
| 順番でないノードを `start` | 拒否 — 代わりに今始められるノードを教えてくれる |
| 今回の訪問の測定なしで `done` | 拒否 — 古い測定値は持ち越されず、古い緑でリトライを通過できない |
| グラフで宣言していないフィールドを `measure` | 拒否 — 宣言のないフィールドを測るのは、手続きを踏んだ当てずっぽうにすぎない |
| `init` 後にグラフを直して続行 | **STALE** 表示 — 状態は自分がどのグラフハッシュから生まれたか覚えている |
| ゲートを `max_retry` 回より多く失敗 | **停止** — 実行が止まり、決定が人間に渡る |

受理された測定はすべて台帳に追記されます。台帳は決して書き換えられず、`init --force` も状態を捨てるだけで台帳は残します。そして台帳は自分自身を守ります: すべての行が直前の行と**ハッシュチェーン**(`h`/`prev`)で結ばれ、状態ファイルがチェーンの先頭を固定します。過去の項目を書き換え・削除・並べ替えれば、人間が確認するまで全コマンドが拒否します。

ツールのメッセージは既定で英語です(`AVALON_LANG=ko` で韓国語。日本語は未対応です)。ビルド成果物は常に英語です — バイトがハッシュされるため、環境に依存してはならないからです。

## 実際にはこう見える

<img src="images/where-it-sits.svg" alt="あなたが一行の目標を渡すと、エージェントがリポジトリで働き、「完了しました」はAvalonのゲートを通ってしかあなたに届かない" width="100%" />

AvalonはAIエージェントを置き換えません — エージェントの「完了しました」とあなたの信頼のあいだに割り込みます。仕事は今まで通りエージェントが全部やり、その主張があなたに届く途中でゲートを通るだけです。

### Claude Codeで

スキルをインストール済みなら([インストール](#インストール))、呼び出しは普通の言葉一行だけです:

```text
avalonで進めて — my-apiに検索エンドポイントを追加、テストは全部グリーンで。
```

言い回しは自由です(「avalonの手順で」「グラフでいこう」…) — スキルのトリガーは名前です。その後は追加の指示なしで:

<img src="images/session-flow.svg" alt="実際のセッション: 一行渡すとエージェントが実測・設計し、ツールが判定し、未達ゲートはループバックし、不可逆ステップで承認を求め、最終報告にcompleted trueと空のabandonedが載る" width="100%" />

1. エージェントが `scaffold` を回し、グラフの草案を描き、何かをする前に4つの数字を見せます。
2. ノードを1つずつ回って測定値を提出し、ツールが合否を答えます。
3. 不可逆ノードで止まってあなたに尋ねます — この停止は礼儀ではなく、出力コードにコンパイルされたものです。
4. 最終報告に `completed` と `abandoned[]` の証拠リストが載ります — エージェントが偽造できない2つの欄。

あなたの実際の役割: ステップ1でゲート設計を一度読む(しきい値への異論はあなたの仕事)、承認の質問に答える、最後に4つの数字を読む。

### 開発者でなくても使えます

「検索エンドポイント」が何のことか分からなくても大丈夫 — 命令はただの日常語でいいのです。状況は2つに分かれます:

**プロジェクトをゼロから始めるとき** — まだ何も無いとき。目標を言って「本当に動くかの確認まで」を付けるだけ:

```text
avalonでやって — うちのカフェのホームページをゼロから作って。
メニュー紹介、アクセス、「お問い合わせ」フォーム。3つとも本当に動くかの確認まで。
```

**作りかけのプロジェクトに何か足すとき** — そのプロジェクトのフォルダでClaude Codeを開いて頼むだけ。エージェントは手を付ける前に、すでにあるものを実測(`scaffold`)します:

```text
avalonでやって — 作りかけのホームページに「予約」機能を付けて。
予約を入れたら一覧に本当に積まれるかの確認まで。
```

こんな使い方もあります:

- 取り消しが怖い修正: *「avalonで — 決済まわりを直して。取り消せないステップの前には私に聞いて。」*
- 寝ている間に任せる: *「avalonで — このリストを夜通し処理して。基準未達なら流さずに止まって。」*

数字・ゲート・グラフの設計はエージェントの仕事です。その代わりエージェントは、**作業を始める前に**基準を分かる言葉で見せなければなりません — 「送信を押したら保存された問い合わせが1件増えること、失敗した検査0件」のように。あなたのやることは3つだけ:

1. 開始前に出てきた基準リストを読み、「うん、それが『完成』で合ってる」と答える。
2. 途中で「このステップは取り消せませんが進めますか?」と聞かれたら答える。
3. 終わったら信号を読む — 緑4つなら完了、`abandoned` に何かあれば「ここはできなかった、証拠はこれ」という意味です。

あなたが絶対に触らないもの: `graph.json`(エージェントが書く)、コマンド(エージェントが打つ)、しきい値(エージェントが提案 — あなたはそれがあなたの思う「完成」かどうかを答えるだけ)。

### GPTなど他のエージェントで

ハーネスにClaude専用のものはありません — ツールは普通のNode CLI 6個、APIキーもベンダー呼び出しもなし。シェルコマンドを実行できるエージェントならどこでも手順を指させます:

```text
https://github.com/Evanciel/avalon をクローンして SKILL.md を読み、
その手順どおりにこのタスクを進めて: <タスク内容>
```

どのエージェントも同じ扱いを受けます: バリデータがグラフ草案に拒否権を行使し、ランナーが近道を拒否し、コンパイルされた `completed` はエージェントの意見を無視します。AIが全くいなくても、ランナーCLIは人間用の規律チェックリストとしてそのまま動きます。

## チュートリアル: 実際に1回回す

以下はすべて実際に起きたことです — コマンドと出力はライブセッションからそのまま、失敗も含めて。(以下の出力は韓国語メッセージ時代に採取したものです — ツールは現在既定で英語になり、`AVALON_LANG=ko` で韓国語になります。訳を添えています。)

小さなNodeプロジェクト `my-api` があり、エージェントに検索エンドポイントを追加してテストを通させたいとします。

**1. スキャフォールド。** リポジトリとタスク一行を渡す:

```bash
node tools/scaffold.mjs ../my-api "検索APIを追加してテストを通す" ../my-api/graph.json
```

すでに検証を通る3ノードのスケルトン(`survey → check → review`)が出ます。スタックと規模は実測済み、ハッシュも2つ刻印済み。

**2. 設計。** プレースホルダを本物の計画に置き換える — ノード3つ、ゲート1つ:

```jsonc
"state": [{ "field": "tests_failed", "type": "int", "unit": "count" }],
"gates": [{
  "id": "G1", "field": "tests_failed", "op": "==", "threshold": 0,
  "on_fail": { "goto": "implement", "max_retry": 2 },
  "ground_truth": "measured",
  "threshold_source": "スイート全数通過 — 部分通過はリリース基準ではない"
}],
"edges": [
  { "from": "implement", "to": "test", "when": "always"       },
  { "from": "test", "to": "implement", "when": "gate:G1:fail" },
  { "from": "test", "to": "ship",      "when": "gate:G1:pass" }
]
```

**3. スタンプ → 検証。** このチュートリアルを書きながら実際にミスをしました — ノード名を変えて `graph.entry` を忘れたのです。バリデータが実行前に捕まえました:

```
$ node tools/validate.mjs graph.json
  FAIL  到達可能性
         ↳ graph.entry 'survey': そんなノードは無い
  static_checks_passed  5/6      G4c FAIL
```

entryを直し、再スタンプ(`hash.mjs --write`)、再検証 → `6/6`、カバレッジ `1.00`。

**4. コンパイル。**

```
$ node tools/compile.mjs graph.json build/graph.workflow.js
  gate_loss  0      PASS
  hook_loss  0      PASS
  compiled → build/graph.workflow.js
  hooks    → build/hooks.json
```

**5. 実行。** ランナーのセッション(注釈のみ追加):

```
$ run.mjs graph.json init
$ run.mjs graph.json start ship          # 順番を飛ばそうとすると
🔴 フロンティアに無いノードだ: ship — 今できるのは: implement

$ run.mjs graph.json start implement     # ok — 実作業はここで
$ run.mjs graph.json done implement      # 次が開く: test

$ run.mjs graph.json start test
$ run.mjs graph.json done test           # 測定を忘れると
🔴 ゲートを判定できない — 今回の訪問の測定が無い:
   G1: tests_failed は一度も測っていない

$ run.mjs graph.json measure tests_failed 3 "npm test: 3 failing"
$ run.mjs graph.json done test
🔴 G1: tests_failed=3 == 0 → fail        # implement に戻る (リトライ 1/2)

# ...コードを直して、implement → test をもう一度通って...
$ run.mjs graph.json measure tests_failed 0 "npm test: all green"
$ run.mjs graph.json done test
🟢 G1: tests_failed=0 == 0 → pass

$ run.mjs graph.json status
  ▶ ship  (human/manual)  ⏸ 人間待ち       # 不可逆 → 出口は人間が受け取る
```

起きなかったことに注目してください: 誰もエージェントに「終わった?」と聞いていません。3を出せばツールがfailと言い、0を出せばpassと言った — それだけです。

**6. セッションの外からも強制する(任意)。** コンパイルはすでに `build/hooks.json` を出しています。インストールするとゲートがセッションのStopフックに配線されますが — インストーラは明示的な承認なしには動きません:

```
$ node tools/install-hooks.mjs graph.json build/hooks.json
インストール計画(まだ何も書いていない):
  対象    .claude/settings.json
  フック  Stop → node tools/hooks-gate.mjs graph.json build/hooks.json
  ゲート  G1
承認が必要 — ユーザー確認後: 同じコマンドに --yes    (exit 3)
```

`--yes` でインストールすると、それ以降ゲートが赤い間はセッションがターンを終えられません(`hooks-gate.mjs` がexit 2で停止をブロック)。インストール後にグラフが変わるとゲートはSTALEを報告し、古いルールで通す代わりにブロックします — 再コンパイル → 再インストールが解消経路です。削除はいつでも `--uninstall --yes`。

## グラフのフォーマット

正本はJSONファイル1つです。構成要素:

**ノード** — やること。`kind` は `work`・`human`・`join`(v1.1にあった `gate` ノードは廃止 — ゲートは今やエッジの管轄です)。ノードごとに `budget` と `retry.max` があり、不可逆なステップには `policy.requires_approval: true` を付けます — コンパイラがこれを本物の停止に変えます。

**エッジ** — 順序。`when` は `always` か `gate:<id>:pass` / `gate:<id>:fail`。語彙はこれだけで、「時々」はありません。

**ゲート** — 合格条件。JSONオブジェクト1つ、自由記述欄なし、都合よく解釈する余地なし:

```jsonc
{
  "id": "G1",
  "field": "tests_failed",          // state[]で宣言済みのフィールドのみ — 未知のフィールドは拒否
  "op": "==",                        // ==  >=  <=  >  <  のいずれか
  "threshold": 0,
  "on_fail": { "goto": "fix", "max_retry": 2 },
  "ground_truth": "measured",        // measured | reported | human | assumed
  "threshold_source": "なぜこの数字か — 根拠を一度は文章で書かせる"
}
```

`max_retry: 0` は*停止*ではなく*分岐*です — 「失敗したらリトライせずその道を行く」(縮小リリースの経路、NO-GOレポート)。ただしリトライ0の分岐がすでに終わったノードへ戻るなら、それは予算のないループなので、ランナーは止まります。

`done` を打つと、ツールが `tests_failed` の最新測定値を読み、`== 0` を適用して答えます。しきい値への異論は実行前に。実行中に判定へ抗議する方法はありません。

**状態(state)** — 測定可能なフィールドのホワイトリストで、それぞれ型があります: `int`・`ratio`・`bool`・`enum`・`ref`・`text`。ゲートを掛けられるのは `int`/`ratio`/`bool` だけ — 散文にしきい値は掛けられないので、`enum`/`ref`/`text` はまずカウンタに派生させる必要があります。単位の間違いもスキーマが捕まえます。`ratio`(0〜1)のフィールドにパーセントのしきい値90を与えると永遠に通らないゲートになる — 実際にあったバグです。

**指紋(fingerprint)** — 対象リポジトリの実測事実(スタック、規模、固定マーカー12種)。`scaffold` が埋め、推測は禁止です。規模は区間(`100-299` ファイル)で書きます — 正確な数は明日には違いますが、区間は長く正しいままです。

**ホスト(host)** — 強制が住む場所: `state_file`(ランナーの状態の置き場)、`enforced_by_hook`(機械強制するゲート、それぞれ `{ "gate": "G0", "check": "node tools/validate.mjs graph.json" }` の形 — コマンドのない宣言こそ `hook_loss` が数えるもの)、`produces`。

**スペックハッシュ** — `hash.mjs` がグラフのcanonical形(キー順は無関係、配列順は保存 — 順序には意味があるので)にsha256を刻印します。下流のすべての産物がこのハッシュを持ち、だからランナーは実行中に変わったグラフを検知でき(STALE)、フックはどのグラフを強制するのか正確に照合されます。

**スキーマバージョニング** — `spec.version` が検証語彙を選びます。古いv1.1グラフはv1.1のルールで検証されます(回帰測定の正本なので、拒否するとベースラインが消えます)。ただしv1.1は*実行不可*と印されます — 「どのリポジトリで何を」を書く場所が無いため、コンパイラが拒否します。検証を通ることと実行して安全なことは別の主張であり、ツールはこの2つを混ぜません。

## 4つの数字

**実行前に4つの数字がすべて緑である必要があります:**

| | 合格条件 | 意味 |
|---|---|---|
| `ir_field_coverage` | 1.00 | 必須13フィールドがすべて埋まっている |
| `static_checks_passed` | 6/6 | グラフの構造に問題がない |
| `gate_loss` | 0 | 宣言したゲートがすべて実行コードに載った |
| `hook_loss` | 0 | 宣言したフックすべてに本物のコマンドが付いている |

lossが0でないなら、「宣言はあるが誰も強制しない」状態です。そのグラフは飾りであり、ツールが非ゼロのexitコードでそう言います。

## ツールを1つずつ

独立ファイル6個、相互依存はimportのみ、どれもLLMを呼びません(INV-1)。決定的というのは文字通りです: 同じ入力なら同じバイトが出ます。

### `scaffold.mjs` — 推測ではなく実測

対象リポジトリを歩き(`node_modules`・`.git`・ビルド産物はスキップ、5万ファイルを歩かないよう上限あり)、スタックを検出し、規模を区間化し、ハッシュを刻み、**すでに検証を通る**グラフスケルトンを出します。ノードはプレースホルダです — そこが判断で、あなたの仕事です。しかし高くつくボイラープレート(必須13フィールド、ハッシュ、retry/policyのデフォルト、必須のhumanノード1個)は機械が埋めます。緑から始めて緑を保つほうが、赤から始めていつ緑になるか分からないより良い。

### `hash.mjs` — canonical JSON + sha256

正規化(キー順無関係、配列順保存)し、ハッシュし、ハッシュフィールド自身を除いて `sha256:<64hex>` をグラフに刻みます。冪等です — 3回回しても結果は同じ。STALE検知とフック照合はすべてこの刻印に掛かっています。

### `validate.mjs` — G0 + 検査6種 + 意見のあるスキーマ

- **G0**: 必須13フィールド全数。部分的な充足は無意味なので、バーは1.00です。
- **静的検査6種**: ゲートは宣言済み状態フィールドのみ参照 · 不可逆ノードに承認あり · すべてのノードが到達可能 · すべての循環に上限あり(停止性) · すべてのノードに予算 · すべてのエッジが実在ノードを指し `when` の形式が正しい。
- **スキーマレベルの拒否**(検査が走る前に): 記述式ゲート — `フィールド/演算子/しきい値` の代わりに散文を書いたゲートは表現自体ができない · 未知の演算子 · ゲート不可の型へのゲート · booleanのしきい値 · `host.enforced_by_hook` の幽霊ゲート参照 · 新しいグラフでの廃止語彙。
- **品質警告**(非致命): `scope`/`host` の欠落、checkコマンドのないフック宣言。

### `render.mjs` — マークダウンは産物である

JSONを読みやすいマークダウンに決定的にレンダリングします。`--check` は再レンダリングしてコミット済みの `graph.md` と**バイト単位**(sha256)で照合します — これがゲートG0bです。誰かがマークダウンを手で直せば検査が落ちます。文書は計画からずれることができません。文書とは計画のレンダリングそのものだからです。

### `compile.mjs` — 無損失の変換、さもなくば変換拒否

IRからワークフロースクリプトへの純関数です。内部では非決定性は禁止 — `Date` なし、`Math.random` なし、オブジェクトキーの巡回順への依存なし。出力するもの:

- ノードごとにサブエージェント呼び出し1つ、すべてのプロンプトに**共有コンテキストブロック**(指紋・target・task)を注入 — 実測事実が仕事と一緒に移動します;
- `always` エッジが複数あるノードは**並列ファンアウト**、枝は単一のjoinで合流;
- humanノードのゲートを保存(人間が測る `design_approved` もゲートであり、コメントではない);
- `requires_approval` ノードでの**承認停止**、`approved` 引数を尊重(デフォルト: 誰も承認されていない);
- **再開**サポート(`resume_from`・`resume_state`・`resume_loops`);
- **ABANDONED台帳**(下のセクション);
- `build/hooks.json` — フック強制ゲートごとに1エントリ: `{ gate, field, op, threshold, check, expect_exit: 0 }`、スペックハッシュでグラフと結合。

そして自分自身を監査します: IRのすべてのゲートが出力に存在しなければならず(`gate_loss`)、宣言されたすべてのフックがコマンド付きで `hooks.json` に存在しなければなりません(`hook_loss`)。どこかにlossがあれば → exit非ゼロ、産物は信頼しない。

### `run.mjs` — 実行者

フロンティア規律、測定台帳、ゲート判定、STALE検知、停止時の人間への引き渡し。[回し方は3通り](#回し方は3通り)で説明した通りです。ファイル冒頭の不変条件4つが契約であり、自己試験はその1つ1つが実際に噛みつくことを証明するために存在します。

台帳は**ハッシュチェーン**です: 各行が `h = sha256(canonical(line))` と直前の行の `h` を併せ持ち、状態ファイルがチェーンの先頭を固定します。以下は、記録済みの測定値7が後から1に書き換えられたときに実際に起きたことです — `verify` だけでなく全コマンドが拒否します:

```text
$ node tools/run.mjs graph.json next
🔴 ledger chain broken — refusing every command:
  line 3: h mismatch — the line was edited
  the ledger is the evidence layer; a run on tampered evidence proves nothing.
  → inspect the ledger, archive it elsewhere, remove it, then re-init
```

(台帳チェーンが壊れた — 全コマンドを拒否。3行目のhが不一致 = 行が書き換えられた。)

1つ注意点があり、チェーンが住むコードにも明記してあります: これは改竄の*証拠(tamper-evident)*であって、改竄の*不可能化(tamper-proof)*ではありません。書き換え・削除・並べ替え・切り詰めは捕まえますが、台帳と状態ファイルを*一緒に整合的に*書き換える者には届きません — それには外部アンカーが必要で、それこそが休眠中の④ARCHIVEに予約された仕事です。

### `install-hooks.mjs` + `hooks-gate.mjs` — セッションを超える強制

インストーラは `build/hooks.json` を**プロジェクトの** `.claude/settings.json` にStopフックとして配線します。要点はその境界です: `--yes` なしには何も書かない(計画だけ見せてexit 3 — エージェントがユーザーの了承なしに `--yes` を付けるのは禁止)、グローバルの `~/.claude` settingsは `--yes` があっても拒否、ハッシュが現在のグラフと合わない古い仕様は拒否、他人のフック項目は保存、再インストールは冪等。`--uninstall --yes` でいつでも外せます。

さらに**承認したものそれ自体を刻印します**: 承認時点の `build/hooks.json` のバイトハッシュが、インストールされる命令にそのまま埋め込まれます(`--approved sha256:…`)。以後ファイルがどんな形で変わっても、ゲートは**checkを1つも実行する前に** TAMPERED としてブロックします — これがなければ、JSONファイル1つへの書き込み権限が、毎ターン終了時に任意の命令を自動実行させる権限と等しくなってしまいます。戻る道は再承認(`--yes` 再インストール)だけです。

さらに、各checkが**赤くなれる**ことの証明も要求します。フック項目には `probe` を宣言できます — 同じオラクルを既知の壊れた入力に向けたもので、したがって必ずexit非ゼロでなければなりません。インストーラはplan時とインストール時に宣言済みプローブを全部回します。exit 0 のプローブは「失敗できないcheck」をその場で実証したことになり、インストールは拒否されます:

```text
$ node tools/install-hooks.mjs graph.json build/hooks.json --yes
installer refused: probe refuted nothing — these checks cannot fail (or the probe never finished), so they enforce nothing:
  G1: probe exit 0 ← node -e "process.exit(0)"
```

(インストーラ拒否: プローブが何も反証しなかった — このcheckは失敗できず、何も強制しない。)

健全な計画はゲートごとに反対証拠を印字します:

```text
  probe   G0  exit 1 ✅ (the oracle can fail)
  probe   G0b  exit 1 ✅ (the oracle can fail)
  probe   G4c  exit 1 ✅ (the oracle can fail)
```

プローブの無いフックもインストールは通ります(「未証明」と報告されるだけで、遡及破壊はありません)。そして `--status` はいつでも読み取り専用の診断を返します: インストール有無、承認ピンが無事かTAMPEREDか、仕様が最新かSTALEか — checkを1つも実行せずに。

インストール後は、セッションがターンを終えようとするたびに `hooks-gate.mjs` が宣言済みcheckを全部回します: 全部通過 → exit 0、1つでも未達 → exit 2で終了をブロックし、未達ゲートをモデルに返します。グラフが変わればSTALEを報告してブロック — 昨日のルールを黙って強制するより、止まるほうが正直です。

## ルールが生まれた場所

これらのルールは机上で設計されたものではありません。すべて実際に起きたバグから生まれ、同じ*種類*のバグが繰り返されると番号が付きます:

| # | 何が起きたか | 今は何が防ぐか |
|---|---|---|
| 1 | 絶対に失敗できない検査があった — 別の検査がすでに強制する条件をもう一度尋ねていた | ループを実際に断つ条件へ検査を書き直した |
| 2 | プロジェクトの指紋を測定してIRに保存までしたのに、プロンプトには一文字も載らなかった | 共有コンテキストブロック + 回帰テスト |
| 3 | 「どのリポジトリで何を」を書く欄がIRに無かった — コンパイルされたエージェントは目隠しで開始した | `target`・`task` を必須化、無ければコンパイル拒否 |
| 4 | 承認必須の宣言が検証を通った後、コンパイラが黙って捨てた — 不可逆な `git push` が停止なしで通った | 承認ゲートをコードに出力 + 回帰テスト |
| 5 | フック強制がIRに宣言され検査も全部緑だったのに、フックファイルは一度も存在しなかった | 宣言に実行可能なコマンドを必須で付け、その隙間を `hook_loss` が数える |

共通パターンは1つ: **宣言は検証され、その後捨てられる。** lossメトリクスは、この種のバグを見逃せなくするために存在します。

## 諦めは成功ではない

<img src="images/abandon.svg" alt="リトライを使い切ったゲートは証拠をabandoned[]に残し、そのリストが空でない限り最終のcompletedは強制的にfalseになる" width="100%" />

ゲートがリトライを使い切っても `on_exhaust: partial` なら、ワークフローは前へ進みます — ただし `{ゲート, ノード, フィールド, 演算子, しきい値, 実測値, 試行回数}` を `abandoned[]` に記録し、そのリストが空でない限り最終の `completed` は**強制的にfalse**になります。ゲートを飛ばした実行が自分を成功と報告する方法はありません。これはコンパイル出力を実際に実行するテストで固定されています。

## フック: 仕様はインストールではない

<img src="images/stop-hook.svg" alt="エージェントがターンを終えようとすると、hooks-gateがすべてのcheckを回す: 全部グリーンならターンが終わり、1つでも赤ならexit 2でブロックされ未達ゲートがモデルに返される" width="100%" />

`compile.mjs` は `build/hooks.json` — ゲートごとのcheckコマンド + exitコード契約 — までしか出さず、そこで止まるのが意図です。インストールは別のツールが別の承認の下で行います: `install-hooks.mjs` は計画を見せ、人間が確認した `--yes` までは何も書かず、プロジェクトのsettingsにのみ(グローバル禁止)インストールし、インストールと同じ手軽さでアンインストールできます。自動インストールは今も禁止です。自分をセッションの強制レイヤーに黙って組み込むツールこそ、このプロジェクトが防ぐために存在する種類の説明不能な魔法だからです。インストールされるまで仕様は何もブロックしません — そして完了報告にはこの文をそのまま書くことが求められます。

Avalon自身の3つのフックにもすべてプローブが付いています: 各checkはコミット済みの壊れたフィクスチャ([tools/fixtures/](tools/fixtures/))にも向けられ、それを拒否しなければならないので、このリポジトリの強制レイヤーは「赤くなれる」ことが証明済みです。

## AvalonはAvalonの上で回る

リポジトリルートの [graph.json](graph.json) はサンプルではありません — Avalon自身の開発をAvalonが管理するグラフです。ノード7個(`frontend → validate → render_check → backend → compile_check → human_go → install_hooks`)、宣言済み状態フィールド6個、そしてゲート3個(G0・G0b・G4c)が `host.enforced_by_hook` で機械強制されます — それぞれ実際に検査するコマンドに加え、そのコマンドが失敗できることを証明するプローブ(コミット済みの壊れたフィクスチャ狙い)付きで。[graph.md](graph.md) はそのレンダリングで、G0bがバイト単位で検証します。

グラフの `guarantees` ブロックは、正直な限界リストの機械寄りの形です: `provides` は緑の実行が正確に何を証明するか、`excludes` は何を証明しないかを書きます。このリポジトリ自身のゲートが赤くなれば、CIが落ちます。

## どうテストしているか

`npm test` 1つで回る3つのスイート、合計158件:

- **[test.mjs](tools/test.mjs) (93件)** — スキーマとコンパイラの挙動、そして**実行意味論**: コンパイルされたワークフロー出力をスタブホストで実際に実行します。「abandonedが空でなければcompletedはfalse」のような主張が、断言ではなく実演されます。新顔は**指紋の弁別力**です — 同じリポジトリを2回実測すればバイトまで同じ指紋、別のリポジトリなら別の指紋にならなければなりません。実際のscaffold実行で測ります。指紋の弁別力は、このテストまで*未検証*の主張でした。デプロイ同期ゲートはランタイムファイル9個をインストール済みスキルのコピーとバイト照合し、リポジトリと配備物が静かにずれるのを防ぎます。
- **[run.selftest.mjs](tools/run.selftest.mjs) (41件)** — ランナーの拒否の壁を、壁の存在を証明する唯一の方法でテストします: *ガードを消せばスイートが赤くならなければならない。* 各テストは禁止された状況(フロンティア外のstart、測定なしのdone、グラフを直して続行)を構成し、ランナーが拒否したときだけ通ります。台帳チェーンのテストは本物の台帳を攻撃します — 過去の測定値を書き換え、末尾を切り詰め、チェーンを迂回して追記します — そして全コマンドが拒否して初めて通ります。
- **[install.selftest.mjs](tools/install.selftest.mjs) (24件)** — インストーラの境界を同じ方法で: `--yes` なしの書き込み禁止、グローバル拒否、古い仕様の拒否、他人のフック保存、冪等な再インストール、そしてゲートの未達・STALEブロック(exit 2)。3件はTOCTOU攻撃シナリオです: 承認の*後で* `build/hooks.json` を書き換え — checkを悪意ある命令に差し替え、グラフごと整合的に再生成までして — ゲートが**何も実行せずに**ブロックしたときだけ通ります(仕込んだ命令が走らなかったことをマーカーファイルで証明)。残りはプローブの壁(失敗できないオラクルは飾りとして拒否)、`--status` が書かずに読むだけであること、そして既定言語が本当に英語であることを固定します。

CIはubuntuとwindowsで両スイートを回します。改行は [.gitattributes](.gitattributes) でLFに固定しています — G0bはバイト単位のオラクルなので、CRLFのチェックアウトは厳密には別の文書だからです。

## 正直な限界

- ツールが証明するのは**宣言されたオラクル**だけです。checkコマンドがゲートの題名と同じ意味かどうかは、いまも人間が見る必要があります。プローブはこの隙間を狭めます(オラクルが失敗*できる*ことまでは証明します)が、閉じはしません — 決定的ツールには閉じられません。
- `build/hooks.json` は仕様です。`install-hooks.mjs --yes`(人間承認のステップ)でインストールされるまで何もブロックしません。
- エージェントノードが実行時に作る成果物は、コンパイル時に照合できません。
- 台帳チェーンは改竄の*証拠(tamper-evident)*であって*不可能化(tamper-proof)*ではありません: 書き換え・削除・切り詰めは捕まえますが、台帳と状態を一緒に書き換える者は捕まえられません。それを捕まえる外部アンカーは④ARCHIVEの仕事で、④は休眠中です。
- ツールのメッセージは既定で英語です(`AVALON_LANG=ko` で韓国語。日本語は未対応)。コードのコメントと [docs/graph/](docs/graph/) の設計史は韓国語のままです。

完全な最新リストは自己適用グラフの `guarantees` ブロックにあります。
