## どんな問題を解くのか

AIエージェントに大きな仕事を任せると、最後に「完了しました」と言います。問題は、そう言った側と確認した側が同じAIだという点です。試験を受けた学生が採点までやるようなもので、抜けがあっても誰も気づきません。

AIをループで回すとき(夜通しの自動作業、通るまでリトライ)、この問題はさらに大きくなります。判定基準がエージェントの外に無ければ、ループは自分を騙しながら気持ちよく回り続けます。

Avalonは順序をひっくり返します。作業を始める**前に**、計画をグラフとして描きます。ノードはやること、エッジは順序、ゲートは合格条件 — そしてゲートに書けるのは**数字だけ**です。判定は小さなツール群が下します。ツールはLLMを呼ばないので、同じグラフを入れれば必ず同じ答えが返ります。

<img src="images/who-judges.svg" alt="Avalonなしではエージェントが自分の点数を書く。Avalonではエージェントが測定値を出し、決定的なツールが判定する。" width="100%" />

仕事は今まで通りエージェントが全部やります — 自分を採点する権利だけを失うのです。

## ハーネスに何が入っているか

| 部品 | やること |
|---|---|
| **グラフ (JSON IR)** | 計画そのもの。ゲートは `フィールド + 演算子 + 数字` — 「うまくいったか確認」のような文章を書く欄がそもそも無い |
| **バリデータ** | 必須フィールド全数検査(G0) + 静的検査6種 + 記述式ゲートを表現の段階で拒否するスキーマ |
| **コンパイラ** | グラフをマルチエージェントのワークフロー実行コードに変換。ゲートが1つでも変換から漏れたら拒否する (`gate_loss`) |
| **ランナー** | 実行時に順序を強制。順番でないノードは開始できず、測定なしでは完了できず、すべての測定は追記専用の台帳に残る |
| **フック仕様** | ゲートをセッションの**外**からも強制できるよう `build/hooks.json` を出力。コマンドのない宣言は `hook_loss` が捕まえる |
| **スキャフォールド** | 対象リポジトリを実測し、すでに検証を通るスケルトンを生成 — 緑から始めて緑を保つ |

## 4ステージ構成

Avalonは4つのステージとして設計されており、このリポジトリのツールがその実装です:

| ステージ | 役割 | 実装 |
|---|---|---|
| **① FRONTEND** | 宣言 — リポジトリを実測してIRを書く | `scaffold.mjs` + 人間/モデルの判断、拒否権は `validate.mjs` |
| **② BACKEND** | コンパイル — 無損失の変換、さもなくば拒否 | `compile.mjs` (`gate_loss`・`hook_loss`・承認停止・フック仕様) |
| **③ DRIVER** | 実行 — 数字のゲートの下で完了まで駆動 | `run.mjs`、またはオーケストレーションホストで回るコンパイル産物 |
| **④ ARCHIVE** | 蓄積 — 終わった実行が事例となり設計に還流 | **意図的に休眠** — 前提条件(敵対的入力への脅威モデル)が整うまでオフのままです。まだ安全でないステージは中途半端に回さず、休眠と宣言します |

ステージの境界こそが荷重を受ける部分です: 判断が入るのは①だけ、②は無損失か拒否か、③は実行するが判定しない、④はまだ存在を許されていない。境界ごとに少なくとも1つの傷跡があります([ルールが生まれた場所](#ルールが生まれた場所)参照)。

## 実行の流れ

<img src="images/pipeline.svg" alt="1 scaffoldはリポジトリを実測し、2 designは人間の判断、3 validateとcompileは4つの数字を検査し、4 runは順序を強制して台帳に記録する" width="100%" />

4ステップのうち2つは機械、1つはあなた、1つはあなたを見張る機械です。判断が入るのはステップ2 — ノードとゲートを何にするか決める瞬間 — だけ。その周りはすべて決定的に動きます。それが要点です。判断は数字として一度だけ記録され、その後は誰も気分で再判定できません。

## 回し方は3通り

### ① ワンショット、スキルとして — 本来の使い方

目標を伝えれば、残りはエージェントがやります:

1. 対象リポジトリに `scaffold` をかけて実測する。
2. 仕事をノードに分割し、ゲートを書く。ここが判断のステップ — 草案はエージェントが書き、拒否権はバリデータが握る。
3. スタンプ → 検証 → コンパイルで[4つの数字](#4つの数字)を緑にする。
4. コンパイルされたワークフローを実行する: ノードごとにサブエージェント1つ、引き継ぎごとに数字のゲート、グラフが終わるまで。

完了まで自走しますが、例外が2つあり、それこそがこのスキルの存在理由です: 不可逆なステップは止まって人間の承認を待ち、諦めたゲートは `abandoned[]` に残る — エージェントが「まあ十分だろう」を黙って決めることはできません。

### ② コンパイルされたワークフロー

`compile.mjs` はグラフをエージェントオーケストレーションホスト用のワークフロースクリプトに変換します(ノードごとに `agent()` 呼び出し1つ、ファンアウトは `parallel()`)。停止地点からの再開と、特定の不可逆ノードの事前承認をサポートします:

```
Workflow({ scriptPath: "build/graph.workflow.js",
           args: { resume_from, resume_state, resume_loops, approved: ["<ノードid>"] } })
```

`policy.requires_approval: true` のノードは、idが `approved` に無ければ**実行前に止まります**。デフォルトは空集合 — 承認ゲートがいつの間にか無力化しないよう、回帰テストが固定しています。

### ③ ランナーCLI — 手動またはエージェント直接駆動

セッションがサブエージェントを立てず、ノードを直接回す場合:

```bash
node tools/run.mjs graph.json init            # 状態を生成(グラフを直した後は init --force)
node tools/run.mjs graph.json next            # 今できること
node tools/run.mjs graph.json status          # 全体像 + まだ回っていないゲートまで
node tools/run.mjs graph.json start <ノード>  # フロンティア外なら拒否
node tools/run.mjs graph.json measure <フィールド> <値> [メモ]
node tools/run.mjs graph.json done <ノード>   # 合否を決めるのはツール、あなたではない
node tools/run.mjs graph.json abort           # 進行中ノードの取り消し
node tools/run.mjs graph.json lint            # ORの罠検査(1ノードにゲート2個以上)
```

すべてのコマンドに機械可読出力 `--json` があります。ランナーは実質「やらせないことのリスト」で、4つの不変条件(INV-1〜4、[run.mjs](tools/run.mjs))から来ています:

| こうすると | ランナーの答え |
|---|---|
| 順番でないノードを `start` | 拒否 — 代わりに今始められるノードを教えてくれる |
| 今回の訪問の測定なしで `done` | 拒否 — 古い測定値は持ち越されず、古い緑でリトライを通過できない |
| グラフで宣言していないフィールドを `measure` | 拒否 — 宣言のないフィールドを測るのは、手続きを踏んだ当てずっぽうにすぎない |
| `init` 後にグラフを直して続行 | **STALE** 表示 — 状態は自分がどのグラフハッシュから生まれたか覚えている |
| ゲートを `max_retry` 回より多く失敗 | **停止** — 実行が止まり、決定が人間に渡る |

受理された測定はすべて台帳に追記されます。台帳は決して書き換えられず、`init --force` も状態を捨てるだけで台帳は残します。

## グラフのフォーマット

正本はJSONファイル1つです。構成要素:

**ノード** — やること。`kind` は `work`・`human`・`join`(v1.1にあった `gate` ノードは廃止 — ゲートは今やエッジの管轄です)。ノードごとに `budget` と `retry.max` があり、不可逆なステップには `policy.requires_approval: true` を付けます — コンパイラがこれを本物の停止に変えます。

**エッジ** — 順序。`when` は `always` か `gate:<id>:pass` / `gate:<id>:fail`。語彙はこれだけで、「時々」はありません。

**ゲート** — 合格条件。JSONオブジェクト1つ、自由記述欄なし、都合よく解釈する余地なし:

```jsonc
{
  "id": "G1",
  "field": "tests_failed",          // state[]で宣言済みのフィールドのみ — 未知のフィールドは拒否
  "op": "==",                        // ==  >=  <=  >  <  のいずれか
  "threshold": 0,
  "on_fail": { "goto": "fix", "max_retry": 2 },
  "ground_truth": "measured",        // measured | reported | human | assumed
  "threshold_source": "なぜこの数字か — 根拠を一度は文章で書かせる"
}
```

`max_retry: 0` は*停止*ではなく*分岐*です — 「失敗したらリトライせずその道を行く」(縮小リリースの経路、NO-GOレポート)。ただしリトライ0の分岐がすでに終わったノードへ戻るなら、それは予算のないループなので、ランナーは止まります。

`done` を打つと、ツールが `tests_failed` の最新測定値を読み、`== 0` を適用して答えます。しきい値への異論は実行前に。実行中に判定へ抗議する方法はありません。

**状態(state)** — 測定可能なフィールドのホワイトリストで、それぞれ型があります: `int`・`ratio`・`bool`・`enum`・`ref`・`text`。ゲートを掛けられるのは `int`/`ratio`/`bool` だけ — 散文にしきい値は掛けられないので、`enum`/`ref`/`text` はまずカウンタに派生させる必要があります。単位の間違いもスキーマが捕まえます。`ratio`(0〜1)のフィールドにパーセントのしきい値90を与えると永遠に通らないゲートになる — 実際にあったバグです。

**指紋(fingerprint)** — 対象リポジトリの実測事実(スタック、規模、固定マーカー12種)。`scaffold` が埋め、推測は禁止です。規模は区間(`100-299` ファイル)で書きます — 正確な数は明日には違いますが、区間は長く正しいままです。

**ホスト(host)** — 強制が住む場所: `state_file`(ランナーの状態の置き場)、`enforced_by_hook`(機械強制するゲート、それぞれ `{ "gate": "G0", "check": "node tools/validate.mjs graph.json" }` の形 — コマンドのない宣言こそ `hook_loss` が数えるもの)、`produces`。

**スペックハッシュ** — `hash.mjs` がグラフのcanonical形(キー順は無関係、配列順は保存 — 順序には意味があるので)にsha256を刻印します。下流のすべての産物がこのハッシュを持ち、だからランナーは実行中に変わったグラフを検知でき(STALE)、フックはどのグラフを強制するのか正確に照合されます。

**スキーマバージョニング** — `spec.version` が検証語彙を選びます。古いv1.1グラフはv1.1のルールで検証されます(回帰測定の正本なので、拒否するとベースラインが消えます)。ただしv1.1は*実行不可*と印されます — 「どのリポジトリで何を」を書く場所が無いため、コンパイラが拒否します。検証を通ることと実行して安全なことは別の主張であり、ツールはこの2つを混ぜません。

## 4つの数字

**実行前に4つの数字がすべて緑である必要があります:**

| | 合格条件 | 意味 |
|---|---|---|
| `ir_field_coverage` | 1.00 | 必須13フィールドがすべて埋まっている |
| `static_checks_passed` | 6/6 | グラフの構造に問題がない |
| `gate_loss` | 0 | 宣言したゲートがすべて実行コードに載った |
| `hook_loss` | 0 | 宣言したフックすべてに本物のコマンドが付いている |

lossが0でないなら、「宣言はあるが誰も強制しない」状態です。そのグラフは飾りであり、ツールが非ゼロのexitコードでそう言います。

## ツールを1つずつ

独立ファイル6個、相互依存はimportのみ、どれもLLMを呼びません(INV-1)。決定的というのは文字通りです: 同じ入力なら同じバイトが出ます。

### `scaffold.mjs` — 推測ではなく実測

対象リポジトリを歩き(`node_modules`・`.git`・ビルド産物はスキップ、5万ファイルを歩かないよう上限あり)、スタックを検出し、規模を区間化し、ハッシュを刻み、**すでに検証を通る**グラフスケルトンを出します。ノードはプレースホルダです — そこが判断で、あなたの仕事です。しかし高くつくボイラープレート(必須13フィールド、ハッシュ、retry/policyのデフォルト、必須のhumanノード1個)は機械が埋めます。緑から始めて緑を保つほうが、赤から始めていつ緑になるか分からないより良い。

### `hash.mjs` — canonical JSON + sha256

正規化(キー順無関係、配列順保存)し、ハッシュし、ハッシュフィールド自身を除いて `sha256:<64hex>` をグラフに刻みます。冪等です — 3回回しても結果は同じ。STALE検知とフック照合はすべてこの刻印に掛かっています。

### `validate.mjs` — G0 + 検査6種 + 意見のあるスキーマ

- **G0**: 必須13フィールド全数。部分的な充足は無意味なので、バーは1.00です。
- **静的検査6種**: ゲートは宣言済み状態フィールドのみ参照 · 不可逆ノードに承認あり · すべてのノードが到達可能 · すべての循環に上限あり(停止性) · すべてのノードに予算 · すべてのエッジが実在ノードを指し `when` の形式が正しい。
- **スキーマレベルの拒否**(検査が走る前に): 記述式ゲート — `フィールド/演算子/しきい値` の代わりに散文を書いたゲートは表現自体ができない · 未知の演算子 · ゲート不可の型へのゲート · booleanのしきい値 · `host.enforced_by_hook` の幽霊ゲート参照 · 新しいグラフでの廃止語彙。
- **品質警告**(非致命): `scope`/`host` の欠落、checkコマンドのないフック宣言。

### `render.mjs` — マークダウンは産物である

JSONを読みやすいマークダウンに決定的にレンダリングします。`--check` は再レンダリングしてコミット済みの `graph.md` と**バイト単位**(sha256)で照合します — これがゲートG0bです。誰かがマークダウンを手で直せば検査が落ちます。文書は計画からずれることができません。文書とは計画のレンダリングそのものだからです。

### `compile.mjs` — 無損失の変換、さもなくば変換拒否

IRからワークフロースクリプトへの純関数です。内部では非決定性は禁止 — `Date` なし、`Math.random` なし、オブジェクトキーの巡回順への依存なし。出力するもの:

- ノードごとにサブエージェント呼び出し1つ、すべてのプロンプトに**共有コンテキストブロック**(指紋・target・task)を注入 — 実測事実が仕事と一緒に移動します;
- `always` エッジが複数あるノードは**並列ファンアウト**、枝は単一のjoinで合流;
- humanノードのゲートを保存(人間が測る `design_approved` もゲートであり、コメントではない);
- `requires_approval` ノードでの**承認停止**、`approved` 引数を尊重(デフォルト: 誰も承認されていない);
- **再開**サポート(`resume_from`・`resume_state`・`resume_loops`);
- **ABANDONED台帳**(下のセクション);
- `build/hooks.json` — フック強制ゲートごとに1エントリ: `{ gate, field, op, threshold, check, expect_exit: 0 }`、スペックハッシュでグラフと結合。

そして自分自身を監査します: IRのすべてのゲートが出力に存在しなければならず(`gate_loss`)、宣言されたすべてのフックがコマンド付きで `hooks.json` に存在しなければなりません(`hook_loss`)。どこかにlossがあれば → exit非ゼロ、産物は信頼しない。

### `run.mjs` — 実行者

フロンティア規律、測定台帳、ゲート判定、STALE検知、停止時の人間への引き渡し。[回し方は3通り](#回し方は3通り)で説明した通りです。ファイル冒頭の不変条件4つが契約であり、自己試験はその1つ1つが実際に噛みつくことを証明するために存在します。

## ルールが生まれた場所

これらのルールは机上で設計されたものではありません。すべて実際に起きたバグから生まれ、同じ*種類*のバグが繰り返されると番号が付きます:

| # | 何が起きたか | 今は何が防ぐか |
|---|---|---|
| 1 | 絶対に失敗できない検査があった — 別の検査がすでに強制する条件をもう一度尋ねていた | ループを実際に断つ条件へ検査を書き直した |
| 2 | プロジェクトの指紋を測定してIRに保存までしたのに、プロンプトには一文字も載らなかった | 共有コンテキストブロック + 回帰テスト |
| 3 | 「どのリポジトリで何を」を書く欄がIRに無かった — コンパイルされたエージェントは目隠しで開始した | `target`・`task` を必須化、無ければコンパイル拒否 |
| 4 | 承認必須の宣言が検証を通った後、コンパイラが黙って捨てた — 不可逆な `git push` が停止なしで通った | 承認ゲートをコードに出力 + 回帰テスト |
| 5 | フック強制がIRに宣言され検査も全部緑だったのに、フックファイルは一度も存在しなかった | 宣言に実行可能なコマンドを必須で付け、その隙間を `hook_loss` が数える |

共通パターンは1つ: **宣言は検証され、その後捨てられる。** lossメトリクスは、この種のバグを見逃せなくするために存在します。

## 設計の紙の痕跡

[docs/graph/](docs/graph/)に設計史の全体があります — 1,300行超、マーケティングは1行もありません:

- **[avalon-graph.md](docs/graph/avalon-graph.md)** — v4仕様: 改訂ごとに根拠を明記したバージョン履歴、4ステージ構成、ゲート名簿(アクティブ9個、そして測定手順が未定義のため明示的に*保留*の2個 — 手順のないゲートはゲートではないので、あるふりをせず駐車しておく)、ゲート設計から意図的に取り除いたもの、そして隠れた前提を声に出して書いたリスト。
- **[ir-schema.md](docs/graph/ir-schema.md)** — 機械可読IR仕様: 指紋(固定マーカー12種、実測のみ)、`target`/`task`、スキーマバージョニング、状態ホワイトリスト、静的検査6種、マークダウンがJSONからレンダリングされる理由、そしてAvalon自身のグラフを実例として — 自己適用で露呈したことのセクション付き。
- **[phase0-findings-v2.md](docs/graph/phase0-findings-v2.md)** — 売り文句を殺した調査: 「業界標準5層」という枠組みは存在しないと判明 · 「自動設計」という差別化は商用・学術の先行事例と照合して反証され廃棄 · そして反例が見つからなかった主張すら*いまだに*対外的な主張には使いません — 反例の不在は証明ではないので。

この最後の習慣がこのディレクトリ全体の要点です: 文書はAvalonが何であるかだけでなく、何になりかけて、それがなぜ間違いだったかまで記録しています。

## 諦めは成功ではない

<img src="images/abandon.svg" alt="リトライを使い切ったゲートは証拠をabandoned[]に残し、そのリストが空でない限り最終のcompletedは強制的にfalseになる" width="100%" />

ゲートがリトライを使い切っても `on_exhaust: partial` なら、ワークフローは前へ進みます — ただし `{ゲート, ノード, フィールド, 演算子, しきい値, 実測値, 試行回数}` を `abandoned[]` に記録し、そのリストが空でない限り最終の `completed` は**強制的にfalse**になります。ゲートを飛ばした実行が自分を成功と報告する方法はありません。これはコンパイル出力を実際に実行するテストで固定されています。

## フック: 仕様はインストールではない

`compile.mjs` は `build/hooks.json` — ゲートごとのcheckコマンド + exitコード契約 — までしか出しません。そこで止まるのが意図です。生きているセッションのsettingsにフックをインストールするのは別の承認付きステップであり、自動インストールは禁止です。自分をセッションの強制レイヤーに黙って組み込むツールこそ、このプロジェクトが防ぐために存在する種類の説明不能な魔法だからです。インストールされるまで仕様は何もブロックしません — そして完了報告にはこの文をそのまま書くことが求められます。

## AvalonはAvalonの上で回る

リポジトリルートの [graph.json](graph.json) はサンプルではありません — Avalon自身の開発をAvalonが管理するグラフです。ノード7個(`frontend → validate → render_check → backend → compile_check → human_go → install_hooks`)、宣言済み状態フィールド6個、そしてゲート3個(G0・G0b・G4c)が `host.enforced_by_hook` で機械強制されます — それぞれ実際に検査するコマンド付きで。[graph.md](graph.md) はそのレンダリングで、G0bがバイト単位で検証します。

グラフの `guarantees` ブロックは、正直な限界リストの機械寄りの形です: `provides` は緑の実行が正確に何を証明するか、`excludes` は何を証明しないかを書きます。このリポジトリ自身のゲートが赤くなれば、CIが落ちます。

## どうテストしているか

`npm test` 1つで回る2つのスイート、合計124件:

- **[test.mjs](tools/test.mjs) (88件)** — スキーマとコンパイラの挙動、そして**実行意味論**: コンパイルされたワークフロー出力をスタブホストで実際に実行します。「abandonedが空でなければcompletedはfalse」のような主張が、断言ではなく実演されます。デプロイ同期ゲートはランタイムファイル6個をインストール済みスキルのコピーとバイト照合し、リポジトリと配備物が静かにずれるのを防ぎます。
- **[run.selftest.mjs](tools/run.selftest.mjs) (36件)** — ランナーの拒否の壁を、壁の存在を証明する唯一の方法でテストします: *ガードを消せばスイートが赤くならなければならない。* 各テストは禁止された状況(フロンティア外のstart、測定なしのdone、グラフを直して続行、台帳の改竄)を構成し、ランナーが拒否したときだけ通ります。

CIはubuntuとwindowsで両スイートを回します。改行は [.gitattributes](.gitattributes) でLFに固定しています — G0bはバイト単位のオラクルなので、CRLFのチェックアウトは厳密には別の文書だからです。

## 正直な限界

- ツールが証明するのは**宣言されたオラクル**だけです。checkコマンドがゲートの題名と同じ意味かどうかは、いまも人間が見る必要があります。
- `build/hooks.json` は仕様です。インストールされるまで(別の承認付きステップ)何もブロックしません。
- エージェントノードが実行時に作る成果物は、コンパイル時に照合できません。

完全な最新リストは自己適用グラフの `guarantees` ブロックにあります。
